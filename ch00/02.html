二、4.x 相对 3.x 变了什么 ​

这是本篇的核心内容。Spring Boot 4.0 是一次大版本升级，做了两件影响面很大的事：把原来一个巨型 jar 拆成了一批细粒度模块，以及把 Jackson 升到了 3.x。这两件事直接导致大量 3.x 写法失效。

下面这张表里的每一条我都实际验证过，验证方式写在备注里，你可以自己复核。

2.1 starter 改名（附官方原文） ​

官方文档的 starter 清单里，被废弃的条目会在描述末尾标注 “deprecated in favor of ...”。以下是从 Build Systems 页面提取的原文：

旧坐标（已废弃）新坐标官方描述原文
spring-boot-starter-webspring-boot-starter-webmvcStarter for building web, including RESTful, applications using Spring MVC. Uses Tomcat as the default embedded container (deprecated in favor of spring-boot-starter-webmvc)
spring-boot-starter-web-servicesspring-boot-starter-webservicesStarter for using Spring Web Services (deprecated in favor of spring-boot-starter-webservices)
spring-boot-starter-oauth2-clientspring-boot-starter-security-oauth2-clientStarter for using Spring Security's OAuth2/OpenID Connect client features (deprecated in favor of spring-boot-starter-security-oauth2-client)
spring-boot-starter-oauth2-resource-serverspring-boot-starter-security-oauth2-resource-server同上规律：OAuth2 相关 starter 统一加 security- 前缀
spring-boot-starter-oauth2-authorization-serverspring-boot-starter-security-oauth2-authorization-server同上规律

注意：废弃不等于不可用

废弃的坐标仍然可以正常下载和运行（我在 Maven 中央仓库逐个探测过，spring-boot-starter-web 在 4.1.1 下依然返回 HTTP 200）。它们存在只是为了兼容存量项目。新写的代码请用新坐标 —— 这样将来大版本清理时不用改。

澄清一个流传很广的错误说法

网上有文章说 spring-boot-starter-amqp 改名成了 spring-boot-starter-rabbitmq。我实际探测的结果是：spring-boot-starter-rabbitmq 返回 HTTP 404，这个坐标根本不存在；而 spring-boot-starter-amqp 在 4.1.1 下正常存在，官方描述是 “Starter for using Spring AMQP and Rabbit MQ”，也没有 deprecated 标记。用消息队列时请继续使用 spring-boot-starter-amqp。

这件事的教训是：判断一个坐标有没有改名，别信二手文章，去看它的 pom 文件里有没有 deprecated 字样，或者直接查官方 starter 清单表。

2.2 从整体式走向模块化 ​

3.x 时代，Spring Boot 的功能集中在一批大 jar 里；4.x 按功能拆成了许多小模块，每个模块可以单独引入。这带来两个直接变化。

**变化一：新增大量 -test 后缀的测试 starter。**以前写 Web 层测试，引入一个庞大的 spring-boot-starter-test；现在可以只引你需要的那个。以下是本教程会用到的几个：

starter用途
spring-boot-starter-webmvc-test测试 Spring MVC 与 Tomcat（提供 @WebMvcTest、@AutoConfigureMockMvc）
spring-boot-starter-data-jpa-test测试 JPA 相关自动配置
spring-boot-starter-security-test测试 Spring Security（提供 @WithMockUser 等）
spring-boot-starter-actuator-test测试 Actuator 端点
spring-boot-starter-test核心测试支持，JUnit Jupiter、AssertJ、Mockito 都在这里

**变化二：属性/类的包名跟着模块走。**原来 org.springframework.boot.autoconfigure.* 下的自动配置类，现在按模块重新分包。举两个例子：

类或注解3.x 包名4.x 包名
@AutoConfigureMockMvcorg.springframework.boot.test.autoconfigure.web.servletorg.springframework.boot.webmvc.test.autoconfigure
DataSourceAutoConfigurationorg.springframework.boot.autoconfigure.jdbcorg.springframework.boot.jdbc.autoconfigure
@SpringBootTest包名未变，仍是 org.springframework.boot.test.context

最典型的报错长这样

从 3.x 项目里拷过来一段测试代码，编译时提示：

编译错误

bash
error: package org.springframework.boot.test.autoconfigure.web.servlet does not exist

类名没变、方法没变，只是包名换了。遇到“类找不到”先怀疑包名迁移，而不是怀疑依赖没引。查找正确包名最快的办法是解压 jar 搜类名：

bash
find ~/.m2/repository/org/springframework/boot -name "spring-boot-webmvc-test-4.1.1.jar" \
  -exec unzip -l {} \; | grep AutoConfigureMockMvc

2.3 Jackson 升到 3.x ​

Spring Framework 7 把 JSON 处理库换成了 Jackson 3，核心包名发生了迁移：

内容Jackson 2（3.x 时代）Jackson 3（4.x 时代）
ObjectMappercom.fasterxml.jackson.databindtools.jackson.databind
核心包com.fasterxml.jackson.coretools.jackson.core
注解包com.fasterxml.jackson.annotation保持不变

这一点在本机工程的依赖树里可以直接看到 —— 注意 groupId 的差别：

text
[INFO]    +- org.springframework.boot:spring-boot-starter-jackson:jar:4.1.1:compile
[INFO]    |  \- org.springframework.boot:spring-boot-jackson:jar:4.1.1:compile
[INFO]    |     \- tools.jackson.core:jackson-databind:jar:3.1.5:compile
[INFO]    |        +- com.fasterxml.jackson.core:jackson-annotations:jar:2.21:compile
[INFO]    |        \- tools.jackson.core:jackson-core:jar:3.1.5:compile

顺带一个观察：注解包不仅包名没变，连版本号也还留在 2.x 线上（2.21），而 databind 与 core 已经是 3.1.5。

好消息是注解包没动 —— @JsonProperty、@JsonFormat、@JsonIgnore 这些日常用的注解 import 不用改；坏消息是如果你手写过 ObjectMapper 的配置代码，import 必须改。

更需要注意的是配置项的语义变化。Jackson 3 把日期时间相关的开关从 SerializationFeature 挪到了 DateTimeFeature，而 Spring Boot 4.1 的 JacksonProperties 并没有暴露对应配置项。于是这段 3.x 时代的经典配置会直接让应用启动失败：

❌ 4.x 下会启动失败

yaml
spring:
  jackson:
    serialization:
      write-dates-as-timestamps: false   # 报错：No enum constant tools.jackson.databind.SerializationFeature.write-dates-as-timestamps

正确做法是删掉它 —— Jackson 3 默认已输出 ISO-8601 字符串，本来就不需要这行配置。

2.4 其他值得注意的搬迁项 ​

下面这几项经常被二手文章写成“已废弃”，实际情况是换了模块或包名，类本身没有标记 @Deprecated。区别很重要：只换包名的话，按报错改 import 即可；真废弃的话才需要考虑迁移。

项目变化实测核实
RestTemplate保留原包 org.springframework.web.client，未被标记 @Deprecated反编译 spring-web-7.0.9 后 javap -v 查不到 Deprecated 标记；官方措辞是“经典方式”，建议新代码用 RestClient
TestRestTemplate从 org.springframework.boot.test.web.client 迁到 org.springframework.boot.resttestclient（独立模块 spring-boot-resttestclient），也未标记 @Deprecated4.1.1 的 spring-boot-test 里已经找不到这个类；RestTestClient 在 Spring Framework 侧提供（org.springframework.test.web.servlet.client）
management.tracing.enabled改为 management.tracing.export.enabled配错会导致追踪数据不上报
Apache Derby 集成自动配置已移除改用 H2 或外部数据库

核实方法：判断一个类“到底废没废”，看它的字节码里有没有 Deprecated 标记，比读任何二手文章都可靠：

bash
unzip -l spring-web-7.0.9.jar | grep RestTemplate
javap -v org/springframework/web/client/RestTemplate.class | grep -i Deprecated

输出为空就是没废弃。这个方法在本教程后面还会反复用到。

2.5 升级自查清单 ​

如果你手上有一个 3.x 项目要升级，按这个顺序过一遍能覆盖九成以上的报错：

  1. 换父 POM 版本 <parent> 的版本改成 4.1.1，同时确认 java.version 不低于 17。
  2. 替换废弃 starter 用 spring-boot-starter-webmvc 替换 spring-boot-starter-web；OAuth2 相关的加 security- 前缀；Web Services 用 webservices。
  3. 修测试 import 所有 @AutoConfigureMockMvc、@WebMvcTest 的 import 改成 org.springframework.boot.webmvc.test.autoconfigure.*，并在 pom 里补上 spring-boot-starter-webmvc-test。
  4. 清理 Jackson 配置 删掉 spring.jackson.serialization.write-dates-as-timestamps；LocalDateTime 的格式改用字段上的 @JsonFormat。
  5. 编译，按报错逐个修包名 类找不到时，优先用解压 jar 搜类名的办法定位新包名，而不是改依赖。
  6. 跑测试，确认行为差异 测试栈跨了大版本（JUnit Jupiter 6、Mockito 5.23），少数断言写法可能有差异。
