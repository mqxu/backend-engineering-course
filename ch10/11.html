10.11 可观测性与追踪 ​

前面讲的是离散的三件事：健康、指标、日志。Spring Boot 还提供了一层把“一次调用中发生了什么”串起来的东西 —— Observation。

自动插桩 ​

引入 starter-actuator 之后，这些位置已经被自动加上了观测点，不需要写代码：

位置观测名
服务端 HTTP 请求http.server.requests
客户端 HTTP 调用http.client.requests
数据访问spring.data.repository.invocations 等
消息消费（第 8 篇那套）spring.integration 系列

每条观测同时产出指标与追踪 span（如果配了追踪）。相关的属性实测有这些：

属性默认值作用
management.observations.http.server.requests.namehttp.server.requests服务端观测名
management.observations.http.client.requests.namehttp.client.requests客户端观测名
management.observations.key-values.*无加到每条观测上的公共键值
management.observations.enable.<name>无按名字开关某类观测，最长匹配优先
management.observations.annotations.enabledfalse是否启用 @Observed / @Timed 这类注解

最后一条要特别注意：注解式观测默认是关的。写了 @Observed 却没生效，先看这个开关，不要怀疑注解写错了。

一个已经废弃的追踪开关 ​

management.tracing.enabled 在 4.x 里已经废弃，而且废弃级别是 error：

text
management.tracing.enabled  →  deprecated, level=error,
   replacement = management.tracing.export.enabled, since 4.0.0

level=error 的含义是：继续用它会导致启动失败，不是“能用但会打警告”。所以 3.x 升上来的配置必须改这一行：

yaml
management:
  tracing:
    # 4.x 里 management.tracing.enabled 已废弃且为 error 级，启动直接失败
    export:
      enabled: true
    sampling:
      # 采样比例，0.0 到 1.0。生产环境别用 1.0
      probability: 0.1

追踪的依赖 ​

Boot 4 把追踪桥接做成了自己的模块。实测 4.1.1 里可用的是：

坐标说明
spring-boot-micrometer-tracing追踪自动配置的公共部分
spring-boot-micrometer-tracing-opentelemetry接 OpenTelemetry 的桥接与 OTLP/Zipkin 导出
spring-boot-micrometer-tracing-brave接 Brave 的桥接
spring-boot-micrometer-tracing-test测试支持

注意坐标名不是 -bridge-otel。 3.x 时代大家用的是 Micrometer 侧的 io.micrometer:micrometer-tracing-bridge-otel，Boot 4 里对应的模块叫 spring-boot-micrometer-tracing-opentelemetry（实测 -bridge-otel 与 -bridge-brave 请求都返回 404）。包名也在 micrometer 命名空间下：

text
org.springframework.boot.micrometer.tracing.autoconfigure
org.springframework.boot.micrometer.tracing.opentelemetry.autoconfigure.otlp
org.springframework.boot.micrometer.tracing.opentelemetry.autoconfigure.zipkin

这一节的内容没有在本机实跑（追踪需要额外的收集端），坐标与属性都是从 4.1.1 的模块与配置元数据里核实出来的。真要接上去，还要自己准备一个 OTLP 接收端。
