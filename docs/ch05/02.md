# 二、引入 starter 之后的默认行为

加上依赖：

```xml
<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-security</artifactId>
</dependency>
```

**只加依赖、不写任何配置**，应用会立刻变成这样：

1. 所有端点（包括你的业务接口）全部要求登录；
2. 自动生成一个用户名为 `user` 的账号，随机密码打印在启动日志里：

```
Using generated security password: 8f2a1c3e-...
```

3. 未登录访问时，浏览器会收到一个 **HTML 登录页**，而不是 JSON。

第 3 点对前后端分离项目是致命的：前端发 Ajax 请求，拿回来一段 HTML，`JSON.parse` 直接抛异常，报错信息还看不出跟认证有关。

这四条默认行为的存在，正是“必须自己写 `SecurityFilterChain`”的原因——**不是可选优化，是必须做的事**。

> **默认密码在哪**
>
> 只有当容器里**没有** `UserDetailsService`、`AuthenticationManager` 等 Bean 时，Spring Boot 才会创建这个 `user` 账号并打印随机密码。一旦提供了自己的 `UserDetailsService`（本项目有），这段日志就不出现了。
>
> 启动日志里搜不到 `Using generated security password`，说明自定义的用户体系已经接管。
