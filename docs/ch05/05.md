# 五、JWT 是什么，以及它的代价

### 5.1 三段结构

JWT 由三部分组成，用点号分隔：

```
eyJhbGciOiJIUzUxMiJ9 . eyJzdWIiOiJhZG1pbiIsImlzcyI6InJlc291cmNlLWh1YiIsInVpZCI6MSwicm9sZSI6IkFETUlOIiwiaWF0IjoxNzg5MjkxMzI4LCJleHAiOjE3ODkyOTg1Mjh9 . 签名
      header                          payload                              signature
```

把本机真实签发的令牌用 Base64 解开：

**header**：

```json
{"alg":"HS512"}
```

**payload**：

```json
{
  "sub": "admin",
  "iss": "resource-hub",
  "uid": 1,
  "role": "ADMIN",
  "iat": 1789291328,
  "exp": 1789298528
}
```

> **重点：前两段只是 Base64URL 编码，不是加密。**
>
> 任何人都能解开看内容。所以**令牌里绝不能放密码、手机号、身份证号这类信息**。它只保证“内容没被篡改”（靠第三段签名），不保证“内容不可读”。
>
> 教学演示里可以直接 Base64 解码，正是为了让大家亲眼看到这一点。

### 5.2 签名算法是自动选的

注意上面 header 里的 `HS512`。密钥是这样来的：

```java
byte[] bytes = properties.secret().getBytes(StandardCharsets.UTF_8);
this.key = Keys.hmacShaKeyFor(bytes);
```

`Keys.hmacShaKeyFor` 会**根据密钥长度自动选择能支持的最强算法**：

| 密钥长度 | 选用算法 |
| --- | --- |
| ≥ 64 字节 | HS512 |
| ≥ 48 字节 | HS384 |
| ≥ 32 字节 | HS256 |
| < 32 字节 | 直接抛异常 |

本项目默认密钥是 66 字节，所以实际签发的是 **HS512** 令牌。

**密钥不足 32 字节时启动就失败**——这个检查放在 `JwtService` 的构造期，比等到第一次签发令牌时才报错要好。

> **密钥必须通过环境变量注入**
>
> ```yaml
> resource-hub:
>   jwt:
>     secret: ${RESOURCE_HUB_JWT_SECRET:resource-hub-local-dev-secret-key-please-change-in-production-2026}
> ```
>
> 冒号后的部分是**开发默认值**。生产环境用环境变量覆盖：
>
> ```bash
> export RESOURCE_HUB_JWT_SECRET="$(openssl rand -base64 48)"
> ```
>
> 这个值一旦泄漏，任何人都能伪造出合法令牌——它的重要性等同于数据库密码。

### 5.3 无状态的代价

| 优点 | 代价 |
| --- | --- |
| 服务端不存会话，水平扩容无需共享存储 | **无法主动踢人下线**：令牌签发后到过期前一直有效 |
| 天然适合多实例部署 | 改角色后旧令牌里的角色仍是旧的，要等过期或换新令牌 |
| 跨域、跨服务调用方便 | 有效期设置是个两难：长了不安全，短了用户频繁重登 |

应对方式是**双令牌**：短期 `accessToken`（15 分钟）+ 长期 `refreshToken`（7 天，存库可吊销）。这样既能主动踢人，又不用频繁登录。完整实现超出本篇范围，思路先记住。

本项目有效期设为 2 小时（`resource-hub.jwt.expiration: 2h`），登录响应里的 `expiresIn: 7200` 就是它的秒数，前端可据此在过期前提示续期。
