# 四、密码怎么存

### 4.1 绝对不要存明文，也不要自己写哈希

`PasswordEncoder` Bean：

```java
@Bean
public PasswordEncoder passwordEncoder() {
    return new BCryptPasswordEncoder();
}
```

BCrypt 的两个特性：

**一、自带随机盐。** 同一个密码每次加密结果都不同：

```
admin123 -> $2a$10$6nH5xS.MNnr1a/6dQ0L43edl/LdEsfJo1Ogjca5HYHXBYKpjMT8Ja
admin123 -> $2a$10$VE.LZ3vgVRAKfD6U20wTlO1GJui1p9geAQVV088O2DPKwyYJ/Pb0.
```

盐是为了防“彩虹表”：把所有常见密码的哈希预先算好一张表，拿到哈希一查就知道原文。加了随机盐后，同一个密码在不同用户那里哈希不同，这张表就失效了。

**因此校验只能用 `matches(raw, encoded)`**，不能自己加密后比字符串——那样永远比不相等。

**二、计算强度可调。** `$2a$10$` 里的 `10` 表示 2 的 10 次方轮。提高强度更抗暴力破解，但登录会变慢，需要在安全与体验之间取平衡。

### 4.2 哈希怎么生成

初始化数据（`data.sql`）里的哈希不能凭想象写，要真实生成：

```java
var encoder = new BCryptPasswordEncoder();
String hash = encoder.encode("admin123");
System.out.println(hash);
```

本项目 `data.sql` 里的两个账号：

| 用户名 | 明文密码 | 角色 |
| --- | --- | --- |
| `admin` | `admin123` | ADMIN |
| `student` | `user123` | USER |

> **哈希是“一次性”的**
>
> 上面两段哈希是本机生成的真实值，可以直接用。但如果哪天想换密码，不要试图“改几个字符”——必须重新跑一次 `encode()`。
>
> 注解：BCrypt 哈希固定 60 个字符，数据库字段留 100 是为了将来换算法（比如 Argon2）时不用改表结构。
