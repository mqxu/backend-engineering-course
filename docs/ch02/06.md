# 六、常见问题

| 症状 | 原因与解法 |
| --- | --- |
| 接口 404，启动日志正常且没报错 | 控制器不在主类的包路径下。检查包名是否为主类包的多级子包（`com.example.resourcehub.web` ✓，`com.example.web` ✗） |
| 启动日志里 `Found 0 JPA repository interfaces` | 仓库接口不在扫描路径内，或接口没有继承 `Repository` 体系的接口 |
| 报 `required a single bean, but N were found` | 同类型多个候选 Bean。用 `@Primary` 或 `@Qualifier`，或重新审视设计 |
| 报 `No qualifying bean of type ... available` | 该类型的 Bean 根本没注册。检查类上有没有构造型注解、包是否被扫描到 |
| 报 `BeanCurrentlyInCreationException` / 循环依赖 | 两个 Bean 构造器互相依赖。通常是设计问题：把公共部分抽到第三个类，或用 `@Lazy` 打破（治标不治本） |
| 配置类里的 `@Bean` 方法每次调用都创建新对象 | 类上漏了 `@Configuration`，或用了 `proxyBeanMethods = false` 却仍按单例假设使用 |
| 改了 `application.yml` 但配置没生效 | 文件位置不对（必须在 `src/main/resources` 下）、缩进有误、或同名配置在更高优先级的来源里被覆盖（第 3 篇讲优先级） |

> **下一篇要做什么**
>
> 结构立起来了，接下来解决“配置管理”这件事。下一篇对照官方的 *Externalized Configuration*、*Profiles* 与 *Logging* 章节，讲清楚配置的十来个来源与优先级、`@ConfigurationProperties` 的正确用法、多环境配置的分离策略，以及日志怎么配才既方便排查又不淹没信息。
