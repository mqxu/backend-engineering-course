# 二、@SpringBootApplication 三段式拆解

这个注解是个元注解，由三部分组成，各自职责清晰：

| 组成 | 作用 |
| --- | --- |
| `@SpringBootConfiguration` | 声明这是一个配置类。它本身又标注了 `@Configuration`，意味着主类里可以直接写 `@Bean` 方法 |
| `@EnableAutoConfiguration` | 打开自动配置：根据 classpath 上的依赖推断该怎么配置 Spring |
| `@ComponentScan` | 从主类所在包开始向下扫描组件 |

如果不想用 `@SpringBootApplication`（比如要精细控制扫描路径），可以拆开写：

**等价写法**

```java
import org.springframework.boot.SpringApplication;
import org.springframework.boot.autoconfigure.EnableAutoConfiguration;
import org.springframework.context.annotation.ComponentScan;

@EnableAutoConfiguration
@ComponentScan("com.example.resourcehub")
public class ResourceHubApplication {

    public static void main(String[] args) {
        SpringApplication.run(ResourceHubApplication.class, args);
    }

}
```

> **一个应用只加一个**
>
> 官方明确要求：`@SpringBootApplication` 或 `@EnableAutoConfiguration` 在应用中**只应该出现一次**，并且加在主要的配置类上。测试类中若需要不同配置，用 `@SpringBootTest(classes = ...)` 或切片注解，而不是再写一个启动类。

### 2.1 排除不需要的自动配置

有时候某些自动配置会带来副作用。比如一个纯 API 服务暂时不接数据库，但 classpath 上有数据源相关依赖，就可以排除掉：

**排除方式一：注解属性**

```java
import org.springframework.boot.autoconfigure.SpringBootApplication;
import org.springframework.boot.jdbc.autoconfigure.DataSourceAutoConfiguration;

@SpringBootApplication(exclude = { DataSourceAutoConfiguration.class })
public class MyApplication {
}
```

> **注意这个类的包名变了**
>
> 官方文档这个例子里的 import 是 `org.springframework.boot.jdbc.autoconfigure.DataSourceAutoConfiguration`。3.x 时代它在 `org.springframework.boot.autoconfigure.jdbc` 下 —— `jdbc` 这一段从后面挪到了前面。照着 3.x 教程抄这个 import，编译会直接失败。这就是第 0 篇讲的“模块拆分导致包名迁移”的一个具体案例。

另外两种写法：

**排除方式二：类不在 classpath 时用全限定名**

```java
@SpringBootApplication(excludeName = {
        "org.springframework.boot.jdbc.autoconfigure.DataSourceAutoConfiguration"
})
public class MyApplication {
}
```

**排除方式三：配置文件里指定（推荐用于多环境）**

```yaml
spring:
  autoconfigure:
    exclude:
      - org.springframework.boot.jdbc.autoconfigure.DataSourceAutoConfiguration
```

> **注解与配置项可以同时使用**
>
> 官方说明：exclusions 可以同时在注解层面和属性层面定义，两者会叠加。另外注意官方的一个提示：自动配置类虽然是 `public` 的，但**对外稳定的只是它的类名**（用于排除）；类内部的嵌套配置类、`@Bean` 方法都属于内部实现，不要直接用。

### 2.2 自动配置包

官方还提到一个概念：**Auto-configuration Packages**，即各类自动配置在扫描实体、仓库时默认查找的包。它由 `@EnableAutoConfiguration`（或 `@SpringBootApplication`）决定，可以用 `@AutoConfigurationPackage` 追加。

什么时候需要它？典型场景是**多模块工程**：主启动类在 `app` 模块，实体在 `core` 模块的另一个包下。此时单靠主类的包路径扫不到实体，就需要显式声明：

**多模块场景**

```java
@SpringBootApplication
@AutoConfigurationPackage(basePackages = "com.example.core")
public class MyApplication {
}
```
