# 9.6 第三层：整体测试，Mock 环境与真实端口

`@SpringBootTest` 的默认 `webEnvironment` 是 `MOCK`：**加载完整容器，但不启动服务器**。请求由 MockMvc 在内部分发，不经过网络栈。

```java
@SpringBootTest
@AutoConfigureMockMvc
@AutoConfigureRestTestClient
class ResourceApiMockEnvironmentTest {

    @Autowired
    private MockMvc mvc;

    @Autowired
    private RestTestClient restClient;
}
```

四种模式的区别：

| 模式 | 加载什么 | 起服务器吗 | 典型用途 |
| --- | --- | --- | --- |
| `MOCK`（默认） | Web 容器上下文，但只是 mock 环境 | 否 | 整体测试，不想付网络代价 |
| `RANDOM_PORT` | `WebServerApplicationContext` | 是，**随机端口** | 端到端，要测序列化与真实 HTTP |
| `DEFINED_PORT` | `WebServerApplicationContext` | 是，固定端口 | 极少数需要固定端口的场景 |
| `NONE` | 普通 `ApplicationContext` | 否 | 只测非 Web 的部分 |

选 `RANDOM_PORT` 而不是 `DEFINED_PORT` 的原因很实际：固定端口在并行构建时会互相抢，本机 8080 被占用时也会直接失败；随机端口每次挑一个空闲的。

### 一个必须知道的事务差异

```java
@SpringBootTest(webEnvironment = WebEnvironment.RANDOM_PORT)
@AutoConfigureRestTestClient
@AutoConfigureTestRestTemplate
class ResourceApiEndToEndTest {

    @LocalServerPort
    private int port;
}
```

**真实端口模式下，测试方法上的 `@Transactional` 不会回滚服务端写入的数据。** 因为 HTTP 请求由 Tomcat 的线程处理，测试方法在另一个线程上，这是两个独立的事务。所以每个用例都要自己保证数据唯一、并负责清理。

Mock 环境没有这个问题——请求和测试跑在同一个线程里。这是“两端点测试”和“整体测试”最实质的差别，也是同一份代码在两种模式下行为不一致的常见来源。

`@LocalServerPort` 注入的是本次实际生效的端口。需要自己拼 URL 时从它取，不要假设是 8080。
