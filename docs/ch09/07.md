# 9.7 HTTP 测试客户端怎么选

Boot 4 里能用的测试客户端一下子变多了，容易选错。按“要不要起服务器”分两栏：

| 客户端 | 运行方式 | 包名 | 备注 |
| --- | --- | --- | --- |
| `MockMvc` | Mock 环境 | `org.springframework.test.web.servlet.MockMvc` | 传统写法，靠静态导入 |
| `MockMvcTester` | Mock 环境 | `org.springframework.test.web.servlet.assertj.MockMvcTester` | Framework 7 新增，AssertJ 风格 |
| `RestTestClient` | Mock 环境 **或** 真实端口 | `org.springframework.test.web.servlet.client.RestTestClient` | 用法与业务侧的 `RestClient` 对齐 |
| `WebTestClient` | Mock 环境（WebFlux）或真实端口 | `org.springframework.test.web.reactive.server.WebTestClient` | 需要 WebFlux 在 classpath 上 |
| `TestRestTemplate` | 真实端口 | `org.springframework.boot.resttestclient.TestRestTemplate` | 宽容模式：4xx/5xx 不抛异常 |

**同一个 `RestTestClient` 两种模式都能用**是这次的改进点：Mock 环境下它绑在 `MockMvc` 上，真实端口下它走真的 HTTP。测试代码几乎不用改，`exchange()` 之后是同一套断言。

### `TestRestTemplate`：搬了家，但没有废弃

这是第 7 篇就核实过的一件事，这里再确认一次，因为很容易被说成“4.x 废弃了它”：

- `TestRestTemplate` 从 `org.springframework.boot.test.web.client` 迁到了 `org.springframework.boot.resttestclient`
- 它所在的模块从 `spring-boot-test` 里**独立了出来**（4.1.1 的 `spring-boot-test` 里已经找不到这个类）
- 反编译检查过字节码，**没有 `@Deprecated` 标记**

所以判据要说准：**“换了包/模块”不等于“废弃”**。它还在，只是新代码更推荐用 `RestTestClient`。

它有个别处没有的特点——**宽容**：遇到 4xx/5xx 不抛异常，而是把状态码交回来。因为它就是给测试用的，认为“错误响应也是一种观察结果”：

```java
ResponseEntity<String> response =
        restTemplate.getForEntity("/api/activities/{id}", String.class, 888_888L);

assertThat(response.getStatusCode()).isEqualTo(HttpStatus.NOT_FOUND);
assertThat(response.getBody()).contains("40400");
```

用 `RestTemplate` 写这段会抛 `HttpClientErrorException`，还得写 try-catch 才能拿到状态码。

### 用它之前要注意的依赖

官方文档写明：用 `TestRestTemplate` 还需要 `spring-boot-restclient`。这个条件容易被忽略，因为编译期不一定报错、要到运行时才发现。本工程的 pom 里两个坐标都引了，注释里也标了原因。

使用 `TestRestTemplate` 的方式：

```java
@SpringBootTest(webEnvironment = WebEnvironment.RANDOM_PORT)
@AutoConfigureTestRestTemplate
class MyTests {

    @Autowired
    private TestRestTemplate restTemplate;
}
```

对应的 `RestTestClient` 版本只需要把注解换成 `@AutoConfigureRestTestClient`。
