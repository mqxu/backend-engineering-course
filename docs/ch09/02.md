# 9.2 依赖怎么引：总入口与 4.x 的细粒度测试模块

`spring-boot-starter-test` 仍然是总入口，它带来的是测试框架本身：

| 依赖 | 作用 |
| --- | --- |
| JUnit Jupiter 6.0.3 | 测试引擎与注解 |
| AssertJ 3.27.7 | 流式断言 |
| Mockito 5.23.0 | mock 与 spy |
| JSONassert、JsonPath | JSON 结构比对 |
| Awaitility | 异步等待（第 8 篇测 WebSocket 时用过） |

但 **Boot 4 把测试支持按技术栈拆成了一大批细粒度模块**，`@WebMvcTest`、`@DataJpaTest` 这类切片注解不再全都在 `spring-boot-test-autoconfigure` 里躺着。官方文档列出的模块清单：

| 模块 | 提供什么 |
| --- | --- |
| `spring-boot-webmvc-test` | `@WebMvcTest`、`@AutoConfigureMockMvc` |
| `spring-boot-data-jpa-test` | `@DataJpaTest`、`TestEntityManager` |
| `spring-boot-jdbc-test` | `@JdbcTest`、`@AutoConfigureTestDatabase` |
| `spring-boot-data-jdbc-test` | `@DataJdbcTest` |
| `spring-boot-data-r2dbc-test` | `@DataR2dbcTest` |
| `spring-boot-restclient-test` | `@RestClientTest` |
| `spring-boot-security-test` | Spring Security 测试支持 |
| `spring-boot-webflux-test` | `@WebFluxTest`、`@AutoConfigureWebTestClient` |
| `spring-boot-graphql-test` | `@GraphQlTest`、`@AutoConfigureHttpGraphQlTester` |
| `spring-boot-webserver-test` | `@AutoConfigureWebServer` |
| `spring-boot-data-redis-test` 等 | 各自的 `@DataRedisTest` / `@DataMongoTest` … |

同时存在两套命名，别混：

- **带 `starter-` 前缀的**：`spring-boot-starter-test`、`spring-boot-starter-webmvc-test`、`spring-boot-starter-security-test`、`spring-boot-starter-data-jpa-test` 等，它们传递引入下面的模块，日常用这些。
- **不带前缀的模块**：`spring-boot-resttestclient`、`spring-boot-testcontainers`、`spring-boot-webmvc-test` 等，**没有对应的 starter**，需要什么就显式引什么。

本篇工程里测试侧的依赖是这样的：

```xml
<!-- 测试基座：JUnit 6 + AssertJ + Mockito -->
<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-test</artifactId>
    <scope>test</scope>
</dependency>

<!-- MVC 切片：@WebMvcTest、@AutoConfigureMockMvc -->
<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-webmvc-test</artifactId>
    <scope>test</scope>
</dependency>

<!-- JPA 切片：@DataJpaTest、TestEntityManager、@AutoConfigureTestDatabase -->
<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-data-jpa-test</artifactId>
    <scope>test</scope>
</dependency>

<!-- 端到端 HTTP 客户端：@AutoConfigureRestTestClient、@AutoConfigureTestRestTemplate -->
<!-- 注意：这个坐标没有 starter- 前缀 -->
<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-resttestclient</artifactId>
    <scope>test</scope>
</dependency>

<!-- TestRestTemplate 还需要它（官方文档明确写了这条） -->
<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-restclient</artifactId>
    <scope>test</scope>
</dependency>

<!-- Testcontainers 支持：@ServiceConnection、@ImportTestcontainers -->
<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-testcontainers</artifactId>
    <scope>test</scope>
</dependency>
```

一处需要留意的连带影响：`spring-boot-restclient` 不只是“给测试用的”。它一旦进入 classpath，就会**为 `RestClient.Builder` 启用自动配置**。如果主代码里要注入 `RestClient.Builder`，这个依赖必须在主 classpath 上（不能只放在 test scope），否则应用启动时找不到那个原型 bean——第 7 篇已经踩过这一次。
