# 9.11 没有 Docker 的环境，怎么收场

Testcontainers 的前提是本机能跑容器。CI 跑在受限容器里、同事机器上没装 Docker、或者像本篇这台机器一样连不上 Docker Hub——这些都会让测试直接失败。要把“环境不具备”和“代码有 bug”区分开。

### 第一种：显式声明“没有 Docker 就跳过”

```java
@Testcontainers(disabledWithoutDocker = true)
class MySqlContainerIntegrationTest { ... }
```

`disabledWithoutDocker` 是 `@Testcontainers` 自带的属性。加上它之后，没有 Docker 时整类测试会被**跳过**（报告里显示 skipped），而不是失败。这样 CI 上“缺环境”不会被误读成“代码有问题”。

### 第二种：连得上 Docker，但拉不到镜像

这是本篇实测遇到的真实情况：Docker daemon 正常，但 `registry-1.docker.io` 直连超时。

```
Error response from daemon: Get "https://registry-1.docker.io/v2/":
context deadline exceeded
```

Testcontainers 除了被测容器，还要拉一个自己的**资源回收容器**（`testcontainers/ryuk`），它的作用是 JVM 意外退出时兜底清理容器。拉不到它，测试会卡在重试里：

```
WARN  tc.testcontainers/ryuk:0.14.0 : Retrying pull for image: testcontainers/ryuk:0.14.0 (104s remaining)
```

处理顺序建议是这样：

**首选配镜像加速器。** 如果 Docker 已经配了 `registry-mirrors` 但拉取仍然走直连，说明配置没有被读取（改完要重启 Docker），或者加速器里没有缓存这个镜像。可以先手工验证加速器是否可达：

```bash
# 返回 401 是正常的：registry v2 需要认证，能返回状态码就说明网络通
curl -s -o /dev/null -w "%{http_code}\n" --max-time 10 https://docker.1ms.run/v2/
```

**实在拉不到，临时关掉 ryuk：**

```bash
TESTCONTAINERS_RYUK_DISABLED=true mvn test
```

代价要说清楚：关掉 ryuk 只是**失去了 JVM 崩溃时的兜底清理**。正常路径下，`@Container` 的生命周期管理在测试结束时仍然会调用 `stop()` 把容器停掉。所以它适合本地临时跑通，不适合当成长期配置。

本篇全量测试就是这么跑下来的：

```bash
TESTCONTAINERS_RYUK_DISABLED=true mvn test
```

### 第三种：把容器当成可选组件

如果团队里大部分人不跑 Docker，可以把 Testcontainers 相关的用例独立成一套、用 Maven profile 或 JUnit tag 隔离，让默认构建不依赖 Docker。做法本身没有对错，关键是要**显式声明**，不要让它变成“在我机器上是绿的”。
