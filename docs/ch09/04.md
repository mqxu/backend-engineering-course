# 9.4 第二层：Web 切片与一批包名的迁移

`@WebMvcTest` 只装配 Spring MVC 那半边容器。官方列出的扫描范围：

`@Controller`、`@ControllerAdvice`、`JacksonComponent`、`JsonComponent`（已弃用）、`Converter`、`GenericConverter`、`Filter`、`HandlerInterceptor`、`WebMvcConfigurer`、`WebMvcRegistrations`、`HandlerMethodArgumentResolver`。

**不扫描**的：普通 `@Component`、`@Service`、`@Repository`、`@ConfigurationProperties`。所以 `ActivityService` 不会存在，必须自己补一个假的。

```java
@WebMvcTest(ActivityController.class)
class ActivityControllerSliceTest {

    @Autowired
    private MockMvcTester mvc;

    @MockitoBean
    private ActivityService service;
}
```

### 先看包名：这批注解在 4.x 搬了家

这是升级到 Boot 4 时最容易卡住的一类问题——类名没变，只是 `package` 不一样，编译器只会说“找不到符号”。逐个核实过的对照：

| 注解 / 类 | 4.x 之前 | Boot 4.1.1 |
| --- | --- | --- |
| `@WebMvcTest` | `...boot.test.autoconfigure.web.servlet` | `org.springframework.boot.webmvc.test.autoconfigure` |
| `@AutoConfigureMockMvc` | `...boot.test.autoconfigure.web.servlet` | `org.springframework.boot.webmvc.test.autoconfigure` |
| `@DataJpaTest` | `...boot.test.autoconfigure.orm.jpa` | `org.springframework.boot.data.jpa.test.autoconfigure` |
| `TestEntityManager` | `...boot.test.autoconfigure.orm.jpa` | `org.springframework.boot.jpa.test.autoconfigure` |
| `@AutoConfigureTestDatabase` | `...boot.test.autoconfigure.jdbc` | `org.springframework.boot.jdbc.test.autoconfigure` |
| `@MockBean` | `org.springframework.boot.test.mock.mockito` | **已删除**，改用 `@MockitoBean` |
| `@MockitoBean` | —（不存在） | `org.springframework.test.context.bean.override.mockito` |
| `@AutoConfigureRestTestClient` | —（不存在） | `org.springframework.boot.resttestclient.autoconfigure` |
| `@AutoConfigureTestRestTemplate` | `org.springframework.boot.test.web.client` | `org.springframework.boot.resttestclient.autoconfigure` |
| `TestRestTemplate` | `org.springframework.boot.test.web.client` | `org.springframework.boot.resttestclient` |
| `@JsonTest` | `...boot.test.autoconfigure.json` | 未变（仍在 `...boot.test.autoconfigure.json`） |

记忆方法：**4.x 把注解搬到了“技术栈命名空间”下**。`webmvc` 的测试注解在 `boot.webmvc.test.autoconfigure`，`data.jpa` 的在 `boot.data.jpa.test.autoconfigure`。找不到类时，先按这个模式猜一遍，再去翻 jar 确认。

### `@MockitoBean` 与 `@MockBean` 的区别不止名字

`@MockBean` 已经不在了。替代品是 Spring Framework 7 提供的两个注解：

- `@MockitoBean` —— 替换容器里的某个 bean 为 Mockito mock
- `@MockitoSpyBean` —— 替换为 Mockito spy

它们比 `@MockBean` 更细的地方在于**支持按 bean 名字或类型精确定位**，不必再靠“上下文中存在唯一同类型 bean”这个脆弱假设。

### 用 `MockMvcTester` 断言

`MockMvcTester` 是 Framework 7 新增的测试门面，底层还是 `MockMvc`，但断言换成了 AssertJ：

```java
AbstractJsonContentAssert<?> json = assertThat(mvc.get().uri("/api/activities/1").exchange())
        .hasStatusOk()
        .bodyJson();

json.extractingPath("$.code").isEqualTo(0);
json.extractingPath("$.data.title").isEqualTo("Spring Boot 4 实战");
```

**这里有一条实测踩到的坑：`extractingPath` 不能连着写第二次。** 它返回的是“取到的那段值”的断言对象（`JsonPathValueAssert`），不是内容断言。写完一次 `extractingPath`，链就断了：

```java
// 编译不过：JsonPathValueAssert 上没有 extractingPath 方法
assertThat(response).bodyJson()
        .extractingPath("$.code").isEqualTo(0)
        .extractingPath("$.data.title").isEqualTo("...");
```

正确做法是把内容断言先存下来，再逐个提取路径，如上面那段代码所示。

### 切片测试能顺带确认的一件事

参数校验发生在进入控制器方法之前，所以校验失败时 Service 一次都不该被碰到：

```java
@Test
void blankTitleIsRejectedBeforeService() {
    String body = """
            {"title":"","venueName":"大学生活动中心","type":"LECTURE","organizer":"陶然然"}
            """;

    assertThat(mvc.post().uri("/api/activities")
            .contentType(MediaType.APPLICATION_JSON)
            .content(body)
            .exchange())
            .hasStatus(400);

    verifyNoInteractions(service);
}
```

`verifyNoInteractions` 这一句比状态码更能说明问题：它把“校验真的挡在了前面”这件事钉死了。
