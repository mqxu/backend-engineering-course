# 9.5 数据访问切片：`@DataJpaTest`

```java
@DataJpaTest
class ResourceItemRepositorySliceTest {

    @Autowired
    private TestEntityManager entityManager;

    @Autowired
    private ResourceItemRepository repository;
}
```

三个默认行为，值得逐条记住——它们解释了为什么这个类里的测试可以写得这么短：

1. **发现内嵌数据库就用它。** classpath 上有 H2，`@DataJpaTest` 会自己配一个内存 `DataSource`，不用写任何连接配置。
2. **每个测试方法跑在事务里，方法结束自动回滚。** 所以方法之间数据互不可见。这一点可以顺手钉下来：

```java
@Test
void eachTestMethodStartsClean() {
    // 上面几个测试各插了 2 到 4 条数据，如果没回滚，这里必然会看到残留
    assertThat(repository.count()).isZero();
}
```

3. **默认打开 `spring.jpa.show-sql`。** 想看方法名解析出了什么 SQL，直接在日志里看。

### `TestEntityManager` 而不是直接调仓储

```java
private ResourceItem persist(String title, String category, ResourceType type) {
    return entityManager.persistAndFlush(
            new ResourceItem(title, title + " 的说明", category, type, null, "陶然然"));
}
```

用 `TestEntityManager` 准备数据比调 `repository.save(...)` 更干净：**被测对象和造数据的工具应该是两个东西**。如果拿仓储自己造数据、再拿它自己断言，那仓储一旦有 bug，造数据和验证会一起错，测试反而看不出问题。

### 想连真实数据库：`@AutoConfigureTestDatabase`

默认的“换成内嵌数据库”是可以关掉的：

```java
@DataJpaTest
@AutoConfigureTestDatabase(replace = Replace.NONE)
class MyRepositoryTests { ... }
```

`Replace.NONE` 的意思是“别替换，用我配好的那个数据源”。这句话本身不提供数据库，它只是不拦着你去连——真实数据库从哪来，就是 9.9 节的 Testcontainers 要解决的事。

### 这一层到底在测什么

不是“验证 Spring Data 能查数据”——那是框架自己的测试。这一层的价值在于**把方法名解析出来的行为钉死**：

```java
@Test
void pageQueryReturnsOnePageOnly() {
    // ...
    Page<ResourceItem> firstPage = repository.findByCategoryName("技术",
            PageRequest.of(0, 2, Sort.by(Sort.Direction.DESC, "id")));

    assertThat(firstPage.getTotalElements()).isEqualTo(3);
    assertThat(firstPage.getTotalPages()).isEqualTo(2);
    assertThat(firstPage.getContent()).hasSize(2);
}
```

仓储是接口，没有实现类，光看代码看不出它会生成什么 SQL、`IgnoreCase` 到底有没有被翻译成 `UPPER(...) LIKE ...`。这些只能靠测试确认。改了个方法关键字、加了个 `OrderBy`，影响哪几个查询，这里会立刻告诉你。

另外注意 `getTotalElements()` 和 `getContent().size()` 是**两个不同的数**（3 和 2）。拿后者当总数来断言分页，是个很常见的错误。
