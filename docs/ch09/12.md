# 9.12 几个顺手就能用上的测试工具

### `OutputCaptureExtension`：断言打出来的内容

```java
@ExtendWith(OutputCaptureExtension.class)
class TestUtilitiesTest {

    @Test
    void capturesStandardOutput(CapturedOutput output) {
        System.out.println("[开关检查] download-tracking = true");

        assertThat(output).contains("[开关检查]");
        assertThat(output.getOut()).contains("download-tracking = true");
    }
}
```

什么时候用它？**当一个组件的作用就是输出时**——启动横幅、配置摘要、开关生效提示，这些没有返回值可断言，只能看它写出来的东西。

反过来，如果只是为了确认“某段逻辑跑过”，用它去匹配日志是在偷懒。那种情况应该直接断言状态。

### `TestPropertyValues`：往 Environment 里塞属性

```java
MockEnvironment environment = new MockEnvironment();

TestPropertyValues.of(
        "resource-hub.feature.download-tracking=false",
        "spring.datasource.url=jdbc:h2:mem:unit")
        .applyTo(environment);
```

`MockEnvironment` 是不连任何真实配置源的 `Environment` 实现，配合 `TestPropertyValues` 用来构造“配置长什么样”的场景。

### `ConfigDataApplicationContextInitializer`：只想要 `application.yml`，不想要整个应用

```java
@ContextConfiguration(classes = Config.class,
        initializers = ConfigDataApplicationContextInitializer.class)
class MyConfigFileTests { ... }
```

它的职责只有一个：**把 `application.properties` / `application.yml` 载入 `Environment`**。注意它**不提供 `@Value(“${...}”)` 的支持**——想要占位符解析，还得自己配一个 `PropertySourcesPlaceholderConfigurer`，或者干脆用 `@SpringBootTest`（它会自动配）。
