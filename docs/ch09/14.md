# 9.14 小结与下一步

这一篇做的事：

- 测试分四层，用实测耗时说明为什么“能写在低层就不要往上走”（单元 0.68 s / Web 切片 0.31 s / JPA 切片 0.56 s / 整体 2.43 s / 条件装配 0.02 s）
- 4.x 的测试模块拆分：一批 `-test` 后缀的细粒度模块，以及**注解包名的迁移对照表**
- `@MockitoBean` 取代 `@MockBean`；`MockMvcTester` 的 AssertJ 风格；`extractingPath` 不能链式调用
- `@DataJpaTest` 的三个默认行为（内嵌库、事务回滚、显示 SQL），以及 `Replace.NONE` 的含义
- 四种 `webEnvironment` 模式的取舍，**真实端口下 `@Transactional` 不回滚服务端数据**
- 五种 HTTP 测试客户端的适用场景；`TestRestTemplate` 是**搬迁**不是废弃，且额外需要 `spring-boot-restclient`
- `ApplicationContextRunner` 测条件装配（4 个用例 0.02 秒），以及 `havingValue` 是字符串精确比较
- Testcontainers 的用法与实测数据（MySQL 8.4.9，容器地址与数据源一致），容器 Bean 与 JUnit 扩展的生命周期差异
- **Testcontainers 2.0 的四项变化**：数据库容器移出 core、坐标名加了前缀、包名搬进技术栈命名空间、去掉自引用泛型
- 没有 Docker / 拉不到镜像时的三种处理

工程侧新增 `resource-hub-testing`，31 个用例、15.8 秒全绿，四层各有覆盖。

下一篇从“写完的代码怎么上线”接上：Actuator 暴露哪些端点、健康检查怎么自定义、指标怎么读、日志级别怎么在不重启的情况下调整，以及为什么这些端点在暴露之前必须先加安全约束。
