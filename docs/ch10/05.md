# 10.5 info 端点：为什么配了 `info.*` 却看不到

`/actuator/info` 有两个来源：配置属性 `info.*` 和 `InfoContributor` bean。看起来很简单，但有一个坑几乎每个人都会踩一次。

**只配 `info.app.*`，响应里连 `app` 这一段都不会出现。** 必须先打开 `management.info.env.enabled`：

```yaml
management:
  info:
    # env / java / os / process 这四个 contributor 默认是关的。
    # 特别是 env —— 不打开它，下面 info.app.* 那些属性根本不会出现在
    # /actuator/info 的响应里（实测确认：只配 info.* 而不开这个开关，
    # 响应里连 app 这一段都没有）。这个坑很容易踩。
    env:
      enabled: true
    java:
      enabled: true
    os:
      enabled: true

info:
  app:
    name: 校园活动服务平台
    module: 生产就绪示例
    contact: dev@example.com
```

原因在于 `info.app.*` 这些自定义属性是由 `InfoContributor` 里那个名为 `env` 的实现读出来的，它负责把 `info.*` 开头的配置属性搬进响应。开关关着，就没有人去读它们。`java`、`os`、`process`、`build`、`git` 同理，全是默认关闭。

打开之后实测的响应：

```json
{
  "app": { "name": "校园活动服务平台", "module": "生产就绪示例", "contact": "dev@example.com" },
  "java": { "jvm": { "name": "OpenJDK 64-Bit Server VM", "vendor": "BellSoft", "version": "21.0.12.1+1-LTS" }, "version": "21.0.12.1" },
  "os": { "arch": "aarch64", "name": "Mac OS X", "version": "26.3" },
  "activityServer": {
    "features": { "upload": true, "export": true },
    "startedAt": "2026-09-14T02:28:17.377829Z",
    "module": "activity-server-observability"
  }
}
```

其中 `activityServer` 这一段来自自定义的 `InfoContributor`：

```java
@Component
public class AppInfoContributor implements InfoContributor {

    private final ObjectProvider<BuildProperties> buildProperties;

    public AppInfoContributor(ObjectProvider<BuildProperties> buildProperties) {
        this.buildProperties = buildProperties;
    }

    @Override
    public void contribute(Info.Builder builder) {
        builder.withDetail("activityServer", Map.of(
                "module", "activity-server-observability",
                "startedAt", OffsetDateTime.now(ZoneOffset.UTC).toString(),
                "features", Map.of("export", true, "upload", true)
        ));

        BuildProperties build = buildProperties.getIfAvailable();
        if (build != null) {
            builder.withDetail("build", Map.of(
                    "artifact", build.getArtifact(),
                    "version", build.getVersion(),
                    "time", build.getTime().toString()
            ));
        }
    }
}
```

**`InfoContributor` 的包名没变**（仍是 `org.springframework.boot.actuate.info`），这一点和 `HealthIndicator` 不一样，别记混。

**`BuildProperties` 不是总有 bean。** 它依赖 classpath 上存在 `META-INF/build-info.properties`，而这个文件由 `spring-boot-maven-plugin` 的 `build-info` goal 生成。所以上面用 `ObjectProvider` 兜了一下 —— 拿不到就跳过这一段，而不是让应用启动失败。真要用，就在插件里加一行：

```xml
<plugin>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-maven-plugin</artifactId>
    <executions>
        <execution>
            <goals>
                <!-- 生成 META-INF/build-info.properties，让 BuildProperties 有东西可读 -->
                <goal>build-info</goal>
            </goals>
        </execution>
    </executions>
</plugin>
```

`info` 端点还有个实践上的用途：**它是发布核对清单的载体**。把构建版本、生效的配置版本、关键业务开关都塞进去，发布完访问一次就知道线上跑的是不是你要发的那一版，不用去翻日志找启动横幅。
