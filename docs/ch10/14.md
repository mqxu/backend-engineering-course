# 10.14 小结与下一步

这一篇做的事：

- Actuator 的默认暴露面（Web 只有 `health`）、为什么 `*` 在 YAML 里要加引号，以及**未暴露端点返回 404 而非 403**
- **4.x 的三处搬迁**：`HealthIndicator` → `org.springframework.boot.health.contributor`（独立模块 `spring-boot-health`）、`MeterRegistryCustomizer` → `org.springframework.boot.micrometer.metrics.autoconfigure`、`EndpointRequest` → `org.springframework.boot.security.autoconfigure.actuate.web.servlet`（旧位置已删除）
- 健康检查：实测的 7 个内置组件（含 **4.0 新增的 `ssl`**）、自定义 `HealthIndicator`、组件名 = bean 名去后缀、`show-details` 与 `show-components` 的分工
- 存活与就绪探针：**liveness 绝不能带外部依赖**、组状态按组件聚合（实测是 `DOWN` 不是 `OUT_OF_SERVICE`）、`503` 是接负载均衡的关键
- `info` 端点的坑：**不打开 `management.info.env.enabled`，`info.app.*` 根本不会出现**
- 指标的写法：注入注册表而非用静态方法、低基数标签、**同名不同标签会多出 0 值时间线**、`Gauge` 传取值函数、`MeterBinder` 绑定他人数据、公共标签的代价
- Prometheus 端的命名转换规则（点→下划线、`_total`、`_seconds`、`_bucket`），实测 913 行 / 81 个 `TYPE`
- **测试环境里真实指标导出被 `spring-boot-micrometer-metrics-test` 换成了 `SimpleMeterRegistry`**，`spring.test.metrics.export` 默认 `false`
- `loggers` 端点：`configuredLevel` 与 `effectiveLevel` 的差异、`null` 时字段整个消失、分组整组调级、**隐藏 logger 的下划线前缀**（`LogDelegateFactory.getHiddenLog`，`since 5.3.5`）
- 自定义端点：`@Endpoint` 与 `@ReadOperation` / `@WriteOperation`、参数只能是简单类型、`@Endpoint` 与 `@WebEndpoint` 的区别
- 可观测性：`management.observations.*` 属性、注解观测默认关闭、**`management.tracing.enabled` 已废弃且为 error 级**、追踪桥接模块的 4.x 坐标
- 端点安全的三道防线：收敛暴露面、`when-authorized` + 角色、独立管理端口

工程侧新增 `resource-hub-observability`，22 个用例、6.9 秒全绿，覆盖健康检查、指标、四个端点与隐藏 logger 的行为。

到这里，一个能跑、能测、能观测的后端已经完整了。但还有个问题没回答：它现在只能在你本机的 IDE 里跑，**怎么变成一个可以交出去的东西**？

下一篇处理打包与部署：可执行 jar 的内部结构、分层 jar 与镜像的关系、容器化时那两个必须注意的镜像构建细节、原生镜像的取舍，以及为什么“打成 jar 就能跑”和“能在生产上跑”之间还差一批配置。
