# 10.1 依赖与暴露面：先把该藏的藏起来

依赖只有一个坐标：

```xml
<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-actuator</artifactId>
</dependency>
```

它自己会传递引入下面这些模块，所以**它们都不该在你的 `pom.xml` 里重复出现**：

| 模块 | 提供什么 |
| --- | --- |
| `spring-boot-actuator-autoconfigure` | 端点的自动配置 |
| `spring-boot-health` | `HealthIndicator`、`Health` 与健康状态聚合（4.x 独立成模块） |
| `spring-boot-starter-micrometer-metrics` | 指标支持与注册表 |
| `micrometer-observation` | Observation API |

Prometheus 导出需要额外一个坐标，它由 Micrometer 提供，Boot 只管版本：

```xml
<dependency>
    <groupId>io.micrometer</groupId>
    <artifactId>micrometer-registry-prometheus</artifactId>
</dependency>
```

实测解析出来的版本：`micrometer-core`、`micrometer-registry-prometheus` 都是 **1.17.1**（Boot 4.1.1 的 `<micrometer.version>` 就是 1.17.1）；如果后面要用追踪，`micrometer-tracing` 是 **1.7.1**。

### 默认只暴露一个端点

Actuator 的默认行为很容易被误解。不加任何配置时：

- **HTTP 只暴露 `/actuator/health`**（`health` 与 `info` 在 JMX 上默认也不暴露，但 `health` 在 Web 上默认可见）
- **JMX 暴露全部端点**（除了 `shutdown`）

所以第一次访问 `/actuator/metrics` 拿到 404 是正常的，不是配置写错了。要开放就得显式列出来：

```yaml
management:
  endpoints:
    web:
      exposure:
        # 生产环境绝对不要写 "*"：env、configprops、heapdump 会泄露
        # 连接串、密钥、内存快照。这里逐个列出是为了让"暴露面"可控可读。
        # YAML 里 * 有特殊含义，真要写通配必须加引号：include: "*"
        include: health,info,metrics,prometheus,loggers,maintenance
      base-path: /actuator
```

**`*` 在 YAML 里是别名（alias）语法**，`include: *` 会直接解析失败，必须写成 `include: "*"`。这个坑很小，但报错信息只会告诉你 YAML 解析出错，不会告诉你是这里。

实测这台机器上暴露这些端点后，`/actuator` 发现页返回的链接有：

```text
health, health-path, info, loggers, loggers-name, maintenance,
metrics, metrics-requiredMetricName, prometheus, self
```

注意 `health-path`（`/actuator/health/{*path}`，用于访问健康分组）与 `metrics-requiredMetricName`（`/actuator/metrics/{requiredMetricName}`）这两个“带路径变量”的虚拟条目 —— 它们是端点模板，不是新的端点。

### 没暴露的端点返回 404，不是 403

这一条值得单独说，因为它直接决定排查方向。

```java
@Test
@DisplayName("未列入 exposure.include 的端点会返回 404，不是 403")
void unexposedEndpointIsNotFound() {
    // env 端点本身是存在的，只是没写进 exposure.include。
    // 注意：不可访问的端点是被"从上下文里摘掉"的，
    // 所以表现是 404 而不是 403 —— 这两者的排查方向完全不同。
    assertThat(mvc.get().uri("/actuator/env").exchange()).hasStatus(404);
}
```

实测 `/actuator/env` 与 `/actuator/beans` 都是 **404**。原因是不在 `include` 列表里的端点根本不会被注册成 MVC 的处理器映射，路由层面就不存在。

这意味着两件事：

1. 看到 404 先查 `exposure.include`，不要先去查安全配置 —— 那会白费工夫。
2. 反过来，**403 一定是安全层拦的**。两种状态码对应两种完全不同的原因，不要混。
