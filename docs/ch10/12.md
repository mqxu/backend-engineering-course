# 10.12 端点安全：把暴露面收回来

这一节回到最开始的问题：默认只暴露 `health` 是合理的，但为了排查问题，总会开放更多。开放到什么程度、用什么保护，得有个明确的答案。

### `EndpointRequest` 换了模块和包名

这是 4.x 里端点安全最容易卡住的一处。实测核实：`EndpointRequest` 现在在 **`spring-boot-security` 模块**里，包名是：

```text
org.springframework.boot.security.autoconfigure.actuate.web.servlet.EndpointRequest
```

3.x 时代它在 `org.springframework.boot.actuate.autoconfigure.security.servlet.EndpointRequest`。而且**旧位置已经不存在了** —— 我在 `spring-boot-actuator` 与 `spring-boot-actuator-autoconfigure` 两个 jar 里都搜不到它，所以这属于“彻底搬迁”，不是“保留旧的加废弃标记”。升级时这类改动必须手工改 import。

### 配法

```java
@Configuration(proxyBeanMethods = false)
@EnableWebSecurity
public class ActuatorSecurityConfig {

    @Bean
    SecurityFilterChain actuatorSecurity(HttpSecurity http) throws Exception {
        http.securityMatcher(EndpointRequest.toAnyEndpoint()
                        .excluding("health", "info"))   // 健康检查留给平台探针匿名访问
                .authorizeHttpRequests(requests -> requests
                        .requestMatchers(EndpointRequest.to("health", "info")).permitAll()
                        // 只有运维角色能看到详情类端点
                        .requestMatchers(EndpointRequest.toAnyEndpoint()).hasRole("OPS"))
                .httpBasic(Customizer.withDefaults());
        return http.build();
    }
}
```

三个 API 的用法：

| 写法 | 匹配 |
| --- | --- |
| `EndpointRequest.to("health", "info")` | 指定 id 的端点 |
| `EndpointRequest.toAnyEndpoint()` | 所有端点 |
| `EndpointRequest.toAnyEndpoint().excluding("health")` | 所有端点减去指定的 |
| `EndpointRequest.toLinks()` | 发现页 `/actuator` 本身 |

**别忘了 `/actuator` 发现页。** 它本身会列出所有端点名字，属于信息泄露。`EndpointRequest.toLinks()` 就是匹配它的 —— 上面的 `toAnyEndpoint()` 不含发现页，需要的话得单独加一条。

安全 7 只保留 Lambda DSL（第 4 篇讲过），链式 `.and()` 已经删掉了，上面的写法是 4.x 唯一可用的形式。

### 三道防线

端点暴露的问题不是一道配置能解决的，按这三层来想：

**第一层：只暴露需要的。** 逐个列出 `exposure.include`，不要用 `"*"`。`env`、`configprops` 会输出连接串和密钥，`heapdump` 会输出内存快照 —— 后者的泄露等于把所有敏感数据交出去。

**第二层：保护 `show-details`。** `management.endpoint.health.show-details` 用 `when-authorized` 而不是 `always`，配合角色：

```yaml
management:
  endpoint:
    health:
      show-details: when-authorized
      roles: ops
```

这样匿名请求只看得到 `{"status":"UP"}`，带 `ops` 角色的请求才看得到组件详情。

**第三层：把管理端点挪到独立端口。** 这是最彻底的做法 —— 端点的流量与业务流量在端口层面就分开了，能单独配防火墙规则：

```yaml
management:
  server:
    port: 8081
    # 只在管理端口上绑定内网地址，公网访问不到
    address: 127.0.0.1
```

代价是每个实例多一个端口，容器编排里要多暴露一个端口、多一条探针配置。取舍看环境：内部系统用前两层通常够，对外服务建议上第三层。

**还有一件事别忘了**：`shutdown` 端点（`POST /actuator/shutdown`）默认**不暴露**，也**不要暴露**。它会让任何能访问的人关掉你的服务。
