# 10.2 4.x 把 Actuator 拆成了什么样

这是本篇最容易卡住的地方：类名没变、IDE 找不到符号、编译报 `package does not exist`。原因是 Boot 4 把原来集中在 `spring-boot-actuator-autoconfigure` 里的东西按技术栈拆成了独立模块，包名也跟着走了。

实测核实的结果：

| 类 / 注解 | 4.x 的位置 |
| --- | --- |
| `HealthIndicator` / `Health` | `org.springframework.boot.health.contributor`（在 `spring-boot-health` 模块） |
| `HealthContributor` | `org.springframework.boot.health.contributor` |
| `InfoContributor` / `Info` | `org.springframework.boot.actuate.info`（**没变**） |
| `@Endpoint` / `@ReadOperation` / `@WriteOperation` | `org.springframework.boot.actuate.endpoint.annotation`（**没变**） |
| `MeterRegistryCustomizer` | `org.springframework.boot.micrometer.metrics.autoconfigure` |
| `EndpointRequest` | `org.springframework.boot.security.autoconfigure.actuate.web.servlet` |

三条要点：

**`org.springframework.boot.actuate.*` 没有整体搬迁。** `@Endpoint`、`@ReadOperation`、`InfoContributor` 这些还在原处。搬走的是健康检查和 Micrometer 自动配置这两块 —— 它们各自有独立模块了。

**`HealthIndicator` 的包名变化最容易被忽略。** 类名一个字没变，只是从 `org.springframework.boot.actuate.health` 搬到了 `org.springframework.boot.health.contributor`。遇到“找不到符号 `HealthIndicator`”先怀疑这一条。

**`MeterRegistryCustomizer` 搬进了 `micrometer` 命名空间。** 新包是 `org.springframework.boot.micrometer.metrics.autoconfigure`，所在的 `spring-boot-micrometer-metrics` 模块由 `starter-actuator` 传递引入，不需要单独加依赖。

### 怎么快速定位

不需要每次去翻文档。最可靠的办法是把 jar 拉下来直接看：

```bash
# 看某个模块的包结构
curl -s -o m.jar https://repo1.maven.org/maven2/org/springframework/boot/\
spring-boot-micrometer-metrics/4.1.1/spring-boot-micrometer-metrics-4.1.1.jar
unzip -l m.jar | grep -oE "org/springframework/boot/[a-z0-9/]+/" | sort -u

# 某个类到底在哪个模块（在本机 m2 里全量搜）
for j in $(find ~/.m2/repository/org/springframework/boot -name "*4.1.1.jar"); do
    unzip -l "$j" 2>/dev/null | grep -q "MeterRegistryCustomizer.class" && echo "$j"
done
```

比查文档快，而且不会猜错。本篇正文里所有包名都是这样核实过的。
