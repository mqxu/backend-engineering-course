# 10.10 自定义端点：`@Endpoint`

需要“只有运维会用、不该进业务 API”的操作时，做成 Actuator 端点比再开一个 REST 接口更合适：

```java
@Component
@Endpoint(id = "maintenance")
public class MaintenanceEndpoint {

    private final AtomicBoolean enabled = new AtomicBoolean(false);
    private volatile String reason = "";
    private volatile String changedAt = "";

    /** GET /actuator/maintenance —— 读当前状态。 */
    @ReadOperation
    public Map<String, Object> status() {
        return Map.of(
                "enabled", enabled.get(),
                "reason", reason,
                "changedAt", changedAt
        );
    }

    /**
     * POST /actuator/maintenance —— 切换维护模式。
     *
     * <p>参数默认都是必填的。想要"不传就保持原值"的语义，
     * 需要把参数标成可空（JSpecify 的 {@code @Nullable}）。
     */
    @WriteOperation
    public Map<String, Object> configure(boolean enabled, String reason) {
        this.enabled.set(enabled);
        this.reason = (reason == null ? "" : reason);
        this.changedAt = OffsetDateTime.now(ZoneOffset.UTC).toString();
        return status();
    }
}
```

值得做成端点的三条理由：

- **端点天然受 `management.endpoints.*` 的可见性与访问级别管控**，不需要单独写一套鉴权规则
- **写操作会一并通过 JMX 暴露**，运维用现成的 JMX 工具就能操作，不必额外开 HTTP 通道
- **响应状态码由框架按操作类型决定**，不用自己挑

方法签名里**只能出现简单类型**。端点是技术无关的 —— 框架要把同一个方法同时映射到 HTTP 与 JMX 上，所以不能出现自定义的 DTO。这也是上面用 `String` 传原因、返回 `Map` 的原因。

`@ReadOperation` 映射成 GET，`@WriteOperation` 映射成 POST，`@DeleteOperation` 映射成 DELETE。**不需要写 `@GetMapping`**，写了反而会破坏 JMX 那条路。

实测这两种操作的响应：

```text
GET  /actuator/maintenance → {"reason":"","changedAt":"","enabled":false}
POST /actuator/maintenance → HTTP 200
GET  /actuator/maintenance → {"reason":"升级数据库","changedAt":"2026-09-13T14:32:03.777233Z","enabled":true}
```

测试里直接调方法也可以，读操作与写操作分开断言：

```java
@Test
@DisplayName("自定义端点按 @ReadOperation / @WriteOperation 映射到 GET 与 POST")
void customEndpointSupportsReadAndWrite() {
    assertThat(maintenance.isEnabled()).isFalse();

    AbstractJsonContentAssert<?> json = assertThat(mvc.post().uri("/actuator/maintenance")
            .contentType(org.springframework.http.MediaType.APPLICATION_JSON)
            .content("""
                    {"enabled":true,"reason":"升级数据库"}
                    """)
            .exchange())
            .hasStatusOk()
            .bodyJson();

    json.extractingPath("$.enabled").isEqualTo(true);
    json.extractingPath("$.reason").isEqualTo("升级数据库");
```

新端点默认是**暴露**的（`enableByDefault` 为 true），但受 `exposure.include` 管控 —— 所以务必把它写进 `include` 列表。不想暴露就加 `@Endpoint(id = "maintenance", enableByDefault = false)`。

`@Endpoint` 与 `@WebEndpoint` 的区别：前者同时暴露到所有技术（HTTP + JMX），后者只暴露到 Web。**只在 Web 上有意义的端点用 `@WebEndpoint`**，比如返回 HTML 页面的、依赖 HTTP 请求上下文的。
