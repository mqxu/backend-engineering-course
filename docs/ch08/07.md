# 8.7 消息转换器：Jackson 2 与 Jackson 3 在这里分岔

Spring AMQP 4.x 里同时存在三个 JSON 消息转换器，选错会浪费不少时间：

| 类 | 面向 | 状态 |
| --- | --- | --- |
| `SimpleMessageConverter` | JDK 序列化 | 默认值，不要用 |
| `Jackson2JsonMessageConverter` | Jackson 2 | **已标记 `@Deprecated`** |
| `JacksonJsonMessageConverter` | Jackson 3 | 推荐 |

`Jackson2JsonMessageConverter` 的废弃标记是实打实的——反编译 `spring-amqp-4.1.1.jar` 能看到 4 处 `Deprecated` 注解。新的 `JacksonJsonMessageConverter` 构造方法是接 `tools.jackson.databind.json.JsonMapper` 的，也就是 Jackson 3 那套包名。

```java
@Bean
public MessageConverter jsonMessageConverter() {
    return new JacksonJsonMessageConverter();
}
```

**为什么一定要换掉默认的 `SimpleMessageConverter`**：它用 Java 原生序列化，会把类名和序列化信息写进消息头。后果是消费端必须能加载生产者用的那个类，跨语言、跨版本升级、类重命名都会出问题；而且消息在 RabbitMQ 管理界面里是一堆二进制，出了问题没法直接看。

配套的 `RabbitTemplate` 会自动关联容器里的 `MessageConverter` Bean，`@RabbitListener` 的容器工厂也一样。**但前提是这个 Bean 存在**——一旦你手工 `new` 一个 `RabbitTemplate`，这个自动关联就不会发生。这一点在第 8.11 节的测试里会真实踩到。
