# 8.4 消费者：容器工厂、并发度与偏移量

```java
@Component
public class ResourceEventConsumer {

    @KafkaListener(topics = KafkaTopics.RESOURCE_EVENTS)
    public void onResourceEvent(ResourceEvent event) {
        // ...
    }
}
```

容器工厂由 Boot 自动配置，参数取自 `spring.kafka.listener.*`。Bean 里只写订阅关系。

**`concurrency` 与分区数的关系**：默认每个监听器 1 个线程。设成 3 才有 3 个线程并行消费，但**真正干活的分区最多 3 个**——线程数超过分区数是浪费，多出来的线程分不到分区，只是白占内存。反过来说，想提高并行度得先加分区，而分区只能增不能减。

**偏移量什么时候提交**：`spring.kafka.listener.ack-mode` 默认是 `BATCH`，即一批消息处理完后统一提交。这意味着**进程被杀时，已处理但未提交的那批会被重新消费**——这就是前面说的“至少一次”。消费逻辑必须幂等，通常做法是用业务主键做去重表，或者让操作本身可重复执行（`upsert` 而不是 `insert`）。
