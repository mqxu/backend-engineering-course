# 8.12 选型与问题速查

### 该选哪个

| 你的需求 | 选择 |
| --- | --- |
| 事件要能被多个消费者独立重放 | Kafka |
| 需要按业务键保证顺序 | Kafka（key 用业务 ID），按分区数并行 |
| 一条消息要根据不同条件路由到不同队列 | RabbitMQ（topic / headers 交换机） |
| 任务分发，处理完就删，需要优先级、延迟队列 | RabbitMQ |
| 日志、埋点、变更流这类高吞吐数据管道 | Kafka |
| 只是想给浏览器推消息 | 都不需要，WebSocket 足够 |

### 问题速查

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| Kafka 日志里没报错，但业务数据不再更新 | 一条坏消息在无限重试，分区被堵住 | 配 `DefaultErrorHandler` + 重试上限 + 死信 |
| 死信主题里找不到消息 | 默认后缀是 `-dlt`（连字符），不是 `.DLT` | 显式指定目的地 |
| 同一资源的事件顺序乱了 | 生产者没指定 key，消息轮询进各分区 | `send(topic, String.valueOf(id), event)` |
| `send()` 没报错但消息丢了 | 返回的 Future 没被 await 或挂回调 | 挂 `whenComplete` 或 `get(timeout)` |
| RabbitMQ 消息发出去了但没人收 | 路由键没有绑定，且没开 `mandatory` | 开 `publisher-returns` + `template.mandatory`，看退回日志 |
| 消息在 RabbitMQ 管理界面里是乱码 | 用了默认的 `SimpleMessageConverter`（JDK 序列化） | 换 `JacksonJsonMessageConverter` |
| 手工 `new` 的 `RabbitTemplate` 报只支持 String/byte[] | 没手工挂 `MessageConverter` Bean | `template.setMessageConverter(...)` |
| 同一条消息被反复处理 | 监听器抛异常后无限重投 | `default-requeue-rejected: false` 或抛 `AmqpRejectAndDontRequeueException` |
| `@KafkaListener` 高并发没生效 | 分区数少于线程数 | 加分区（只能增不能减） |
| WebSocket 单机能用、多实例收不到 | `enableSimpleBroker` 是进程内的 | 换 `enableStompBrokerRelay` |
| 客户端 `subscribe` 后立刻发消息收不到 | 订阅是异步的 | 用回执（需真 broker）或重发直到收到 |
| import 报找不到 `WebSocketStompClient` | Framework 7 换了包 | 用 `org.springframework.web.socket.messaging.WebSocketStompClient` |
| 老的 `KafkaProperties` import 编译不过 | Boot 4 按技术栈拆了模块 | 换成 `org.springframework.boot.kafka.autoconfigure.KafkaProperties` |
| `TestRabbitTemplate` 一直连 broker | 连接工厂是真实的，或 Bean 化后被后处理替换 | 用 mock 工厂，并在 `@BeforeEach` 里重新 `setConnectionFactory` |
