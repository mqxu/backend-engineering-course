# 8.10 WebSocket 与 STOMP：三种前缀的分工

WebSocket 解决的是“服务端主动推给浏览器”。用 STOMP 子协议之后，消息有了目的地（destination）的概念，Spring 也能用类似 MVC 的注解模型来处理。

```java
@Configuration(proxyBeanMethods = false)
@EnableWebSocketMessageBroker
public class WebSocketConfig implements WebSocketMessageBrokerConfigurer {

    @Override
    public void registerStompEndpoints(StompEndpointRegistry registry) {
        registry.addEndpoint("/ws")
                .setAllowedOriginPatterns("*");
    }

    @Override
    public void configureMessageBroker(MessageBrokerRegistry registry) {
        registry.enableSimpleBroker("/topic");
        registry.setApplicationDestinationPrefixes("/app");
    }
}
```

三个前缀各管一段路，搞混是最常见的困惑：

| 前缀 | 作用 | 谁处理 |
| --- | --- | --- |
| `/ws` | 握手地址。客户端连的是这个 URL | 握手拦截器 |
| `/app` | **入口**前缀。客户端 SEND 到 `/app/xxx` → 路由到 `@MessageMapping("/xxx")` | 你的控制器 |
| `/topic` | **出口**前缀。由 message broker 负责投递 | broker |

一个常见的误解是“发到 `/topic/xxx` 就等于广播给所有人”。不对——`/topic` 是**订阅**用的目的地，客户端 subscribe 它才收得到；要发消息必须发到 `/app` 前缀下，由你的方法再把结果送到 `/topic`。

### 两种推送方式

```java
@Controller
public class NoticeController {

    private final SimpMessagingTemplate messagingTemplate;

    /** 客户端发起的广播：SEND 到 /app/notice，返回值被送到 /topic/resources */
    @MessageMapping("/notice")
    @SendTo("/topic/resources")
    public ResourceNotice onNotice(ResourceNotice notice) {
        return notice;
    }

    /** 服务端主动推送：HTTP 接口或定时任务里调用，不经过 @MessageMapping */
    public void broadcast(ResourceNotice notice) {
        messagingTemplate.convertAndSend("/topic/resources", notice);
    }
}
```

两者的选择依据是**有没有客户端请求**：由某个用户的操作触发、要通知其他人，用 `@MessageMapping` + `@SendTo`；后台算出了结果要推给前端（比如第 7 篇那个缓存预热任务跑完了），用 `SimpMessagingTemplate`。

### `enableSimpleBroker` 只适合单实例

`enableSimpleBroker` 用的是进程内的内存 broker，消息不落盘、不跨进程。**多实例部署时它必然出问题**：用户连到 A 实例，消息从 B 实例发出，A 根本不知道，用户就是收不到。这种问题在看日志时非常难定位，因为每个实例自己看起来都正常。

多实例要用真正的外部 broker：`registry.enableStompBrokerRelay("/topic").setRelayHost(...)`，通常接 RabbitMQ 的 STOMP 插件或 ActiveMQ。

**关于 SockJS**：`withSockJS()` 这个方法在 Framework 7 里**没有**被标记废弃（`javap -v` 查过 `StompWebSocketEndpointRegistration`，无 `Deprecated`）。它解决的是很老的浏览器没有原生 WebSocket 的问题，现代浏览器不需要，所以这里没用它。

### 客户端类的包名迁移

如果你要写一个 STOMP 客户端（测试或者另一个服务），注意 **`WebSocketStompClient` 在 Spring Framework 7 里换了包**：

| 版本 | 包名 |
| --- | --- |
| Framework 6.x | `org.springframework.messaging.simp.stomp.WebSocketStompClient` |
| Framework 7.x | `org.springframework.web.socket.messaging.WebSocketStompClient` |

`StompSession`、`StompHeaders`、`StompFrameHandler` 这些都还留在 `org.springframework.messaging.simp.stomp`，只有客户端这一个类搬走了，所以报错会显得很没道理——同一个 import 块里其他类都在，就它找不到。
