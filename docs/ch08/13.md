# 8.13 小结与下一步

这一篇做的事：

- 判断该不该上消息队列的三条标准，以及引入后必然多出来的四件事（重复消费、顺序、失败处理、本地跑不起来）
- Kafka：Boot 4 新增的 `spring-boot-starter-kafka`、key 与分区的关系（实测同 key 三条全落分区 0）、发送返回的 Future 不等确认
- 消费失败的处理：默认无限重试会堵死分区，配 `DefaultErrorHandler` + 死信；**死信默认后缀是 `-dlt` 不是 `.DLT`**
- RabbitMQ：交换机与队列的拓扑声明、死信参数、`Jackson2JsonMessageConverter` 已废弃
- 发布确认与退回的分工；消费者确认、prefetch、重投行为
- WebSocket + STOMP 的三种前缀、两种推送方式、多实例的坑，以及 `WebSocketStompClient` 的包名迁移
- 三条链路的测试手法，7 个用例、约 10 秒、零外部依赖

工程侧新增 `activity-server-messaging`，19 个 Java 文件 996 行，7 个测试全通过。

下一篇处理测试本身：单元测试与集成测试的边界怎么划、切片测试怎么用（以及 `@WebMvcTest` 在 4.x 的包名变化）、端到端测试改用 `RestTestClient`（它会连带讲清 `TestRestTemplate` 只是换了模块和包名，并没有废弃）、以及用 Testcontainers 起真实数据库。
