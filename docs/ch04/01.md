# 一、一次请求在 Spring MVC 里经过了什么

理解这条链路，后面所有配置项才知道该往哪儿放。

```
浏览器
  │  HTTP 请求
  ▼
┌─────────────────────────────────────────────┐
│ Servlet 容器（Tomcat 11）                    │
│   Filter 链  ← Servlet 规范，拿不到 Handler  │
│      │                                       │
│      ▼                                       │
│   DispatcherServlet  ← Spring MVC 的前端控制器│
│      │                                       │
│      ├─ HandlerMapping  找到该由哪个方法处理   │
│      ├─ HandlerInterceptor.preHandle         │
│      ├─ HandlerAdapter 调用 Controller 方法   │
│      ├─ HandlerInterceptor.postHandle        │
│      ├─ 返回值交给 HttpMessageConverter 序列化 │
│      └─ HandlerInterceptor.afterCompletion   │
└─────────────────────────────────────────────┘
  │  HTTP 响应
  ▼
浏览器
```

启动日志里能看到 DispatcherServlet 的初始化——它是在**第一个请求到达时**才初始化的，不是启动时：

```
2026-09-13T16:43:58.355+08:00  INFO 88035 --- [resource-hub] [nio-8080-exec-1] o.s.web.servlet.DispatcherServlet : Initializing Servlet 'dispatcherServlet'
2026-09-13T16:43:58.356+08:00  INFO 88035 --- [resource-hub] [nio-8080-exec-1] o.s.web.servlet.DispatcherServlet : Completed initialization in 1 ms
```

想让它在启动时就初始化（提前暴露配置错误、避免首请求变慢），加上配置：

```yaml
spring:
  mvc:
    servlet:
      load-on-startup: 1
```

### 1.1 过滤器与拦截器怎么选

| | Filter | HandlerInterceptor |
| --- | --- | --- |
| 所属规范 | Servlet（`jakarta.servlet`） | Spring MVC（`org.springframework.web.servlet`） |
| 能拿到什么 | 请求、响应 | 还能拿到 `HandlerMethod`，知道要调哪个类的哪个方法 |
| 典型用途 | 编码、跨域、请求包装、安全过滤链 | 日志、鉴权、参数预处理、多租户上下文 |
| 注册方式 | `@Component` 或 `FilterRegistrationBean` | 实现 `WebMvcConfigurer#addInterceptors` |

**判断标准**：需要知道“要执行哪个方法”就用拦截器；需要在 MVC 之外生效（比如静态资源、错误页）就用过滤器。

### 1.2 不要用 @EnableWebMvc

这是新手最容易踩的坑之一。`@EnableWebMvc` 会**关掉 Spring Boot 的全部 MVC 自动配置**，此后静态资源映射、消息转换器、参数解析器、错误处理全都要自己重配。正确做法是实现 `WebMvcConfigurer`——它只加东西，不改默认行为。
