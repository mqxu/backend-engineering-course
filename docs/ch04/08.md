# 八、拦截器实战：请求耗时统计

`common/RequestTimingInterceptor.java`

```java
@Component
public class RequestTimingInterceptor implements HandlerInterceptor {

    private static final Logger log = LoggerFactory.getLogger(RequestTimingInterceptor.class);
    private static final String START_ATTR = "requestStartNanos";

    /** 请求进入 Controller 之前执行，返回 false 会直接中断后续流程 */
    @Override
    public boolean preHandle(HttpServletRequest request, HttpServletResponse response,
                             Object handler) {
        request.setAttribute(START_ATTR, System.nanoTime());
        return true;
    }

    /**
     * 整个请求处理完毕后执行（视图渲染之后），无论成功还是抛异常都会被调用。
     * 因此它是统计"本次请求实际耗时"最合适的位置。
     */
    @Override
    public void afterCompletion(HttpServletRequest request, HttpServletResponse response,
                                Object handler, Exception ex) {
        Object start = request.getAttribute(START_ATTR);
        long costMs = start instanceof Long s ? (System.nanoTime() - s) / 1_000_000 : -1;
        log.info("{} {} → {} ({} ms)", request.getMethod(), request.getRequestURI(),
                response.getStatus(), costMs);
    }
}
```

注册（`config/WebConfig.java`）：

```java
@Configuration
public class WebConfig implements WebMvcConfigurer {

    private final RequestTimingInterceptor timingInterceptor;

    public WebConfig(RequestTimingInterceptor timingInterceptor) {
        this.timingInterceptor = timingInterceptor;
    }

    @Override
    public void addInterceptors(InterceptorRegistry registry) {
        registry.addInterceptor(timingInterceptor)
                .addPathPatterns("/api/**")
                .excludePathPatterns("/api/files/**")
                .order(1);
    }
}
```

**`afterCompletion` 是统计耗时的正确位置**。它在请求完全处理完（含视图渲染）后调用，且**无论成功还是抛异常都会执行**。写在 `postHandle` 里的话，Controller 抛异常时就不会被调用，统计数据会缺一块。

不是 `afterCompletion` 就一定准——它统计的是“从 preHandle 到请求处理结束”，不含网络传输到客户端的时间。要统计端到端耗时得上 APM 或 Micrometer（第 10 篇）。

**真实日志输出**：

```
2026-09-13T16:44:15.618+08:00  INFO 88035 --- [resource-hub] [io-8080-exec-10] c.e.r.common.RequestTimingInterceptor : GET /api/resources → 200 (115 ms)
2026-09-13T16:44:15.654+08:00  INFO 88035 --- [resource-hub] [nio-8080-exec-2] c.e.r.common.RequestTimingInterceptor : GET /api/categories → 200 (20 ms)
2026-09-13T16:44:15.678+08:00  INFO 88035 --- [resource-hub] [nio-8080-exec-4] c.e.r.common.RequestTimingInterceptor : GET /api/resources/9999 → 404 (11 ms)
```

注意第三条：**请求以 404 结束，但拦截器依然记录了**（`→ 404`）。这正是 `afterCompletion` 的价值——用 `postHandle` 是拿不到这条记录的。

另外注意 `/api/files/**` 被排除了。大文件传输的耗时统计意义不大，日志还很吵。**排除规则写在注册处而不是拦截器内部的 if 判断**，这样看一眼 `WebConfig` 就知道拦截范围。
