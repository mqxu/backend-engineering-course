# 三、REST 接口设计

`web/ResourceController.java`

```java
@RestController
@RequestMapping("/api/resources")
@Validated
public class ResourceController {

    private final ResourceService resourceService;

    public ResourceController(ResourceService resourceService) {
        this.resourceService = resourceService;
    }

    @GetMapping
    public ApiResponse<PageResult<ResourceResponse>> list(
            @RequestParam(required = false) Long categoryId,
            @RequestParam(required = false) ResourceType type,
            @RequestParam(required = false) String keyword,
            @RequestParam(defaultValue = "0")
            @Min(value = 0, message = "页码不能小于 0") int page,
            @RequestParam(defaultValue = "10")
            @Min(value = 1, message = "每页条数不能小于 1")
            @Max(value = 100, message = "每页条数不能大于 100") int size) {

        return ApiResponse.ok(resourceService.search(categoryId, type, keyword, page, size));
    }

    @GetMapping("/{id}")
    public ApiResponse<ResourceResponse> detail(@PathVariable Long id) {
        return ApiResponse.ok(resourceService.getById(id));
    }

    @PostMapping
    @ResponseStatus(HttpStatus.CREATED)
    public ApiResponse<ResourceResponse> create(@Valid @RequestBody ResourceCreateRequest request) {
        return ApiResponse.ok(resourceService.create(request));
    }

    @PutMapping("/{id}")
    public ApiResponse<ResourceResponse> update(@PathVariable Long id,
                                                @Valid @RequestBody ResourceUpdateRequest request) {
        return ApiResponse.ok(resourceService.update(id, request));
    }

    @DeleteMapping("/{id}")
    public ApiResponse<Void> delete(@PathVariable Long id) {
        resourceService.delete(id);
        return ApiResponse.ok();
    }

    @PostMapping("/{id}/download")
    public ApiResponse<ResourceResponse> download(@PathVariable Long id) {
        return ApiResponse.ok(resourceService.download(id));
    }
}
```

### 3.1 接口清单

| 方法 | 路径 | 说明 | 成功状态码 |
| --- | --- | --- | --- |
| GET | `/api/resources` | 分页 + 多条件查询 | 200 |
| GET | `/api/resources/{id}` | 查询详情 | 200 |
| POST | `/api/resources` | 新增 | **201** |
| PUT | `/api/resources/{id}` | 修改 | 200 |
| DELETE | `/api/resources/{id}` | 删除（逻辑删除） | 200 |
| POST | `/api/resources/{id}/download` | 下载计数 +1 | 200 |
| GET | `/api/categories` | 分类列表 | 200 |
| POST | `/api/files` | 上传文件 | **201** |
| GET | `/api/files/{storedName}` | 下载文件 | 200 |
| GET | `/api/files` | 已上传文件列表 | 200 |

### 3.2 三个设计决策

**一、下载为什么用 POST 而不是 GET。**
下载是“产生副作用”（下载量 +1）的操作。做成 `GET /resources/1/download` 的话，浏览器预取、爬虫抓取、用户刷新都会意外增加计数。

**二、删除为什么返回 200 而不是 204。**
严格按 REST 规范删除成功应返回 `204 No Content`，但那样响应体是空的，前端得分两种情况解析。本项目选择统一返回 `200 + ApiResponse`，契约更简单。规范与实用之间的取舍，团队内部统一即可。

**三、`@ResponseStatus(HttpStatus.CREATED)` 的用途。**
创建成功返回 201 而不是 200，让“创建”和“查询”在状态码层面就区分开，监控系统可以直接统计创建量。

> **`@Validated` 与 `@Valid` 是两套机制**
>
> - 类上的 `@Validated`（Spring 的）开启**方法级校验**，让 `@RequestParam`、`@PathVariable` 上的 `@Min`/`@Max`/`@Pattern` 生效，失败抛 `ConstraintViolationException`。
> - 参数上的 `@Valid`（Jakarta 的）触发**请求体 DTO 校验**，失败抛 `MethodArgumentNotValidException`。
>
> 两者异常类型不同，全局异常处理器要分别处理。
