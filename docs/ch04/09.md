# 九、跨域（CORS）

开发期前端跑在 `http://localhost:5173`（Vite 默认端口），后端在 8080，**不同源**。同源策略要求协议、域名、端口三者完全一致，所以浏览器的请求会被拦截。

`config/WebConfig.java`

```java
@Override
public void addCorsMappings(CorsRegistry registry) {
    registry.addMapping("/api/**")
            .allowedOrigins("http://localhost:5173", "http://127.0.0.1:5173")
            .allowedMethods("GET", "POST", "PUT", "DELETE", "OPTIONS")
            .allowedHeaders("*")
            .allowCredentials(true)
            .maxAge(3600);
}
```

**真实预检响应**：

```
curl -X OPTIONS http://127.0.0.1:8080/api/resources \
  -H "Origin: http://localhost:5173" \
  -H "Access-Control-Request-Method: POST" \
  -H "Access-Control-Request-Headers: content-type"
```

```
HTTP/1.1 200
Access-Control-Allow-Origin: http://localhost:5173
Access-Control-Allow-Methods: GET,POST,PUT,DELETE,OPTIONS
Access-Control-Allow-Headers: content-type
Access-Control-Allow-Credentials: true
Access-Control-Max-Age: 3600
```

| 响应头 | 作用 |
| --- | --- |
| `Access-Control-Allow-Origin` | 允许的来源。必须是**具体来源**，不能是 `*`（见下） |
| `Access-Control-Allow-Methods` | 允许的 HTTP 方法 |
| `Access-Control-Allow-Headers` | 允许携带的请求头。`content-type` 必须在列，否则 JSON POST 会被拦 |
| `Access-Control-Allow-Credentials` | 是否允许带 Cookie / Authorization |
| `Access-Control-Max-Age` | 预检结果缓存秒数，减少 OPTIONS 请求 |

> **`allowCredentials(true)` 与 `allowedOrigins("*")` 不能同时用**
>
> 这是 CORS 规范的限制：带凭证的请求必须明确指定来源，不能用通配符。写了组合会在启动时报错。需要放行多个来源时，逐个列出，或用 `allowedOriginPatterns`。

> **“预检请求”是什么**
>
> 跨域的 `POST + application/json`、带自定义头的请求，浏览器会先发一个 `OPTIONS` 请求问服务器“允许吗”，拿到许可后才发真实请求。这就是 `Access-Control-Max-Age` 存在的意义——把预检结果缓存起来，避免每个请求都多一次往返。
>
> **GET 携带简单头（如 `Accept`）不触发预检**，所以有时候“GET 正常、POST 报跨域”，原因就在这里。

**另一种解法：前端配代理。** 让 Vite 把 `/api` 转发到 8080，浏览器看到的是同源请求，后端完全不用改。第 12 篇会给出完整的 `vite.config.js` 配置。两种方式对比：

| | 后端 CORS | 前端代理 |
| --- | --- | --- |
| 配置位置 | 服务端 | 前端开发服务器 |
| 生产环境 | 有效 | 仅开发期有效（生产靠 Nginx 转发） |
| 适用场景 | 前后端独立部署 | 本地开发 |
