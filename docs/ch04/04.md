# 四、参数校验

### 4.1 校验注解写在 DTO 上

`dto/ResourceCreateRequest.java`

```java
public record ResourceCreateRequest(

        @NotBlank(message = "标题不能为空")
        @Size(max = 128, message = "标题长度不能超过 128 个字符")
        String title,

        @Size(max = 512, message = "描述长度不能超过 512 个字符")
        String description,

        @NotNull(message = "必须指定所属分类")
        Long categoryId,

        @NotNull(message = "必须指定资源类型")
        ResourceType type,

        @Size(max = 512, message = "资源地址长度不能超过 512 个字符")
        String url,

        @PositiveOrZero(message = "文件大小不能为负数")
        Long fileSize,

        @NotBlank(message = "上传者不能为空")
        @Size(max = 64, message = "上传者长度不能超过 64 个字符")
        String uploader,

        @Size(max = 128, message = "标签长度不能超过 128 个字符")
        String tags
) {
}
```

**为什么不写在实体上**：实体的“新增”和“修改”校验规则常常不同（比如修改时 id 必填、新增时不能传），绑在实体上就没法区分；而且实体的职责是映射数据库表，把 Web 层规则混进去会让它身兼二职。

### 4.2 常用注解

| 注解 | 适用类型 | 说明 |
| --- | --- | --- |
| `@NotNull` | 任意 | 不为 null。空字符串**能通过** |
| `@NotEmpty` | 字符串、集合 | 不为 null 且长度大于 0 |
| `@NotBlank` | 字符串 | 不为 null 且去除首尾空白后长度大于 0 |
| `@Size(min, max)` | 字符串、集合 | 长度范围 |
| `@Min` / `@Max` | 数值 | 闭区间边界 |
| `@PositiveOrZero` | 数值 | 大于等于 0 |
| `@Email` | 字符串 | 邮箱格式（默认较宽松） |
| `@Past` / `@Future` | 时间类型 | 必须是过去 / 未来时间 |
| `@Pattern(regexp)` | 字符串 | 正则匹配 |

`@NotBlank` 是最常用的一个。注意它在 `record` 上的行为：对 `"  "`（全空格）会判定为不合格。

### 4.3 真实校验失败响应

```
POST /api/resources
{"title":"  ","categoryId":1,"type":"DOCUMENT","uploader":""}
```

```
{"code":40001,"message":"uploader: 上传者不能为空; title: 标题不能为空"}
[HTTP 400]
```

注意这里**一次性返回了全部错误**，而不是只报第一个。前端可以一次把所有出错字段标红，用户不用改一个提交一次。这个效果来自第五节 `MethodArgumentNotValidException` 的处理方式。

### 4.4 自定义校验注解（扩展）

内置注解不满足时，自己写一个。以“资源地址必须是 http/https 或 /files 开头”为例：

```java
@Target({ElementType.FIELD, ElementType.PARAMETER})
@Retention(RetentionPolicy.RUNTIME)
@Constraint(validatedBy = ResourceUrlValidator.class)
public @interface ResourceUrl {
    String message() default "资源地址格式不合法";
    Class<?>[] groups() default {};
    Class<? extends Payload>[] payload() default {};
}

public class ResourceUrlValidator implements ConstraintValidator<ResourceUrl, String> {
    @Override
    public boolean isValid(String value, ConstraintValidatorContext context) {
        if (value == null || value.isBlank()) {
            return true;   // 空值交给 @NotBlank 判断，这里不重复报错
        }
        return value.startsWith("http://") || value.startsWith("https://")
                || value.startsWith("/files/");
    }
}
```

> **一条经验**：自定义校验器里，null 或空值应当**返回 true**，把“必填”的判断交给 `@NotNull`/`@NotBlank`。否则传空时会同时报两条错误，前端提示重复。
