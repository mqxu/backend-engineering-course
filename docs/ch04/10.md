# 十、静态资源与错误页

### 10.1 默认静态资源位置

Spring Boot 自动把以下四个目录暴露为静态资源，按优先级从高到低：

| 位置 | 说明 |
| --- | --- |
| `classpath:/META-INF/resources/` | 依赖 jar 内的静态资源 |
| `classpath:/resources/` | —— |
| `classpath:/static/` | **最常用**，放 CSS、JS、图片 |
| `classpath:/public/` | —— |

`src/main/resources/static/index.html` 会被映射到 `http://localhost:8080/index.html`。

### 10.2 自定义静态资源映射

把本地上传目录也暴露出去（教学演示用）：

```java
@Override
public void addResourceHandlers(ResourceHandlerRegistry registry) {
    registry.addResourceHandler("/uploads/**")
            .addResourceLocations("file:./storage/")
            .setCachePeriod(3600);
}
```

> **生产环境不要这样暴露上传目录**
>
> 用户上传的文件可能含 HTML 或脚本，直接以静态资源形式提供会造成存储型 XSS。生产环境应当：限制上传类型白名单、把文件放在独立域名下提供、加上 `Content-Type: application/octet-stream` 强制浏览器按附件处理，或干脆改用对象存储的私有桶 + 签名 URL。

### 10.3 错误响应

默认错误页面由 `ErrorMvcAutoConfiguration` 提供。要自定义，加配置：

```yaml
server:
  error:
    whitelabel:
      enabled: false        # 关掉默认白页
    include-message: always  # 错误响应里带上 message 字段
```

或实现 `ErrorController` 返回自定义结构。注意本项目已经用 `@RestControllerAdvice` 接管了大部分异常，`/error` 兜底主要处理的是“没进 Controller 就失败”的情况——比如 URL 完全匹配不上任何映射（404）、请求方法不支持（405）。
