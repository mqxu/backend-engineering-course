# 七、文件上传下载

### 7.1 上传

`web/FileController.java`

```java
@RestController
@RequestMapping("/api/files")
public class FileController {

    private final FileStorageService storage;

    public FileController(FileStorageService storage) {
        this.storage = storage;
    }

    @PostMapping
    @ResponseStatus(HttpStatus.CREATED)
    public ApiResponse<FileStorageService.StoredFile> upload(
            @RequestParam("file") MultipartFile file) {
        return ApiResponse.ok(storage.store(file));
    }
}
```

`service/FileStorageService.java` 里的保存逻辑：

```java
public StoredFile store(MultipartFile file) {
    if (file == null || file.isEmpty()) {
        throw BusinessException.badRequest("上传文件不能为空");
    }
    String original = file.getOriginalFilename() == null ? "unnamed" : file.getOriginalFilename();
    String suffix = "";
    int dot = original.lastIndexOf('.');
    if (dot >= 0) {
        suffix = original.substring(dot);
    }
    String stored = UUID.randomUUID().toString().replace("-", "") + suffix;

    try (InputStream in = file.getInputStream()) {
        Files.copy(in, root.resolve(stored), StandardCopyOption.REPLACE_EXISTING);
        writeMeta(stored, original, file.getContentType());
    } catch (IOException e) {
        throw new IllegalStateException("文件写入失败", e);
    }
    return new StoredFile(stored, original, file.getSize(), file.getContentType(), Instant.now());
}
```

**存储名为什么用 UUID 重新生成**：两个理由。一是用户可能上传同名文件，直接用原名会互相覆盖；二是原始文件名可能带路径分隔符或特殊字符（`../../x.txt`、`a:b.txt`），直接当文件名不安全。

**边车文件（`.meta`）**：光在磁盘上存一个 UUID 文件名，是恢复不出“用户当初传的叫什么”的。所以每存一个文件，旁边写一个同名 `.meta` 文件记录原始文件名与类型。不做这一步，文件列表接口就会出现“原始名 == 存储名”的怪现象。

```java
private void writeMeta(String stored, String original, String contentType) throws IOException {
    Properties meta = new Properties();
    meta.setProperty("originalName", original);
    meta.setProperty("contentType", contentType == null ? "application/octet-stream" : contentType);
    try (var writer = Files.newBufferedWriter(metaFile(stored), StandardCharsets.UTF_8)) {
        meta.store(writer, "uploaded file metadata");
    }
}
```

列表查询时要过滤掉 `.meta` 文件，否则它们会当成用户上传的文件出现在列表里。

### 7.2 下载

```java
@GetMapping("/{storedName}")
public ResponseEntity<Resource> download(@PathVariable String storedName) {
    Resource resource = storage.load(storedName);
    // 对外用原始文件名，用户下载下来才认得出是什么
    String filename = storage.originalNameOf(storedName);
    ContentDisposition disposition = ContentDisposition.attachment()
            .filename(filename, StandardCharsets.UTF_8)
            .build();

    return ResponseEntity.ok()
            .header(HttpHeaders.CONTENT_DISPOSITION, disposition.toString())
            .contentType(MediaType.APPLICATION_OCTET_STREAM)
            .body(resource);
}
```

四个要点：

1. **返回 `ResponseEntity<Resource>` 而不是 `ApiResponse`**。响应体是字节流，不是 JSON。用 `Resource` 还能让 Spring 走流式写出，不必把整个文件读进内存。
2. **`ContentDisposition.attachment()`** 决定浏览器是“弹下载框”还是“直接打开”。不指定的话，浏览器可能直接渲染，用户拿不到文件。
3. **文件名用 UTF-8 编码**。`filename(...)` 传入 `StandardCharsets.UTF_8` 后，生成的响应头会同时带 `filename=` 和 `filename*=UTF-8''` 两种形式（见下方真实响应头），兼容各类浏览器。
4. **路径穿越防护**——这是上传下载功能最容易被忽视的安全问题：

```java
public Resource load(String storedName) {
    Path target = root.resolve(storedName).normalize();
    if (!target.startsWith(root)) {
        throw BusinessException.badRequest("非法的文件名");
    }
    if (!Files.isReadable(target)) {
        throw BusinessException.notFound("文件不存在: " + storedName);
    }
    return new UrlResource(target.toUri());
}
```

`normalize()` 会把 `../` 折叠掉，`startsWith(root)` 再确认折叠后的路径仍在存储目录内。少了这两行，`GET /api/files/../../etc/passwd` 就能读到存储目录之外的文件。

### 7.3 上传大小限制

```yaml
spring:
  servlet:
    multipart:
      max-file-size: 20MB
      max-request-size: 25MB
      file-size-threshold: 1MB
```

| 配置 | 含义 |
| --- | --- |
| `max-file-size` | 单个文件上限 |
| `max-request-size` | 整个请求上限（多文件时是总和） |
| `file-size-threshold` | 超过此大小则写入临时文件，否则放内存 |

超限时抛 `MaxUploadSizeExceededException`，被全局异常处理器转成 413（真实响应）：

```
HTTP 413
{"code":41300,"message":"上传文件超过大小限制"}
```

> **默认值是 1MB**
>
> Spring Boot 的默认单文件上限是 **1MB**，不是无限。很多“本地能传、线上传不了”的问题都是这个原因。默认不处理 `MaxUploadSizeExceededException` 时会返回 500，客户端误以为是服务端故障。

### 7.4 上传下载实测

启动应用后逐条验证（以下全部是本机真实输出）。

**上传**：

```
curl -F "file=@/tmp/demo-note.txt" http://127.0.0.1:8080/api/files
```

```json
{
  "code": 0,
  "message": "success",
  "data": {
    "storedName": "a2d19fb5bc32464782c93e8f425f0703.txt",
    "originalName": "demo-note.txt",
    "size": 59,
    "contentType": "text/plain",
    "uploadedAt": "2026-09-13 16:44:02"
  }
}
```

**下载**（响应头）：

```
HTTP/1.1 200
Content-Disposition: attachment; filename="demo-note.txt"; filename*=UTF-8''demo-note.txt
Accept-Ranges: bytes
Content-Type: application/octet-stream
Content-Length: 59
```

`filename*=UTF-8''` 那一段是 RFC 5987 编码形式，含中文文件名时浏览器靠它正确还原文件名。

**列表**：

```json
{
  "code": 0,
  "message": "success",
  "data": [
    {
      "storedName": "a2d19fb5bc32464782c93e8f425f0703.txt",
      "originalName": "demo-note.txt",
      "size": 59,
      "contentType": "text/plain",
      "uploadedAt": "2026-09-13 16:44:02"
    }
  ]
}
```

**存储目录实际内容**：

```
-rw-r--r--  1 moqi  staff   59 Sep 13 16:44 a2d19fb5bc32464782c93e8f425f0703.txt
-rw-r--r--  1 moqi  staff  104 Sep 13 16:44 a2d19fb5bc32464782c93e8f425f0703.txt.meta
```

**路径穿越尝试**：

```
curl "http://127.0.0.1:8080/api/files/..%2F..%2F..%2Fetc%2Fpasswd"
→ HTTP 400
```

这里被 **Tomcat 挡在了容器层**（返回 400），请求根本没进到应用代码——Tomcat 8.5 起默认拒绝含编码路径分隔符 `%2F` 的请求（`ALLOW_ENCODED_SLASH` 默认 `false`）。但**不能因此省掉应用层的 `normalize()` 校验**：容器配置可能被人改掉、应用可能部署在别的容器上、内部调用也不一定经过 HTTP。

**文件不存在**：

```
HTTP 404
{"code":40400,"message":"文件不存在: notexist.txt"}
```

> **时间字段用 `Instant` 还是 `LocalDateTime`**
>
> `uploadedAt` 的类型是 `Instant`（UTC 时间点），但输出时用 `@JsonFormat(pattern = "...", timezone = "Asia/Shanghai")` 转成东八区，与本项目其他接口的格式保持一致：
>
> ```java
> @JsonFormat(pattern = "yyyy-MM-dd HH:mm:ss", timezone = "Asia/Shanghai")
> Instant uploadedAt
> ```
>
> `Instant` 是“绝对时间点”，不依赖时区，适合存储和跨时区计算；`LocalDateTime` 是“墙上时钟时间”，没有时区信息。**两者不要混用**，否则跨时区部署时会出错。本项目的 `createdAt`/`updatedAt` 用 `LocalDateTime`（教学项目不涉及时区转换），`uploadedAt` 用 `Instant` 演示正确做法。
