# 一、外部化配置：搞清楚谁覆盖谁

### 1.1 官方定义的配置源优先级

官方文档给出了完整的 PropertySource 顺序，**序号越小优先级越高**（即 15 最高，1 最低）。以下是原文列表：

| 优先级 | 来源 | 说明 |
| --- | --- | --- |
| 15 | DevTools 全局设置 | `$HOME/.config/spring-boot` 目录下，仅 DevTools 激活时生效 |
| 14 | `@TestPropertySource` | 测试类上的注解 |
| 13 | `@DynamicPropertySource` | 测试中动态注册属性（Testcontainers 常用） |
| 12 | 测试注解的 `properties` 属性 | 如 `@SpringBootTest(properties = ...)` |
| **11** | **命令行参数** | `java -jar app.jar --server.port=9090` |
| 10 | `SPRING_APPLICATION_JSON` | 环境变量或系统属性里的内联 JSON |
| 9 | `ServletConfig` 初始化参数 | —— |
| 8 | `ServletContext` 初始化参数 | —— |
| 7 | JNDI 属性（`java:comp/env`） | 传统应用服务器场景 |
| 6 | Java 系统属性 | `System.getProperties()`，即 `-D` 参数 |
| **5** | **操作系统环境变量** | 容器部署时的主要配置方式 |
| 4 | `RandomValuePropertySource` | 只提供 `random.*` 属性 |
| **3** | **Config data**（`application.yml` 等） | 日常开发最常用的一层 |
| 2 | `@PropertySource` | 注意：这类属性源直到容器刷新时才加入 Environment |
| 1 | 默认属性 | `SpringApplication.setDefaultProperties(Map)` |

> **两个必须记住的结论**
>
> **一、命令行参数优先级高于配置文件。**所以 `java -jar app.jar --server.port=9090` 一定覆盖 `application.yml` 里的 `server.port`。上线排查问题时，先用这个手段临时改配置，不用改包。
>
> **二、环境变量优先级也高于配置文件。**容器里常通过 `SPRING_DATASOURCE_URL` 这类变量注入配置。如果你改了 yml 却不生效，先检查环境变量里有没有同名的项。

### 1.2 application.yml 内部的四层顺序

第 3 层的 “Config data” 内部还有细分，从高到低是：

1. **jar 包外、带 Profile 的文件** `./config/application-dev.yml` → `./application-dev.yml`
2. **jar 包外、不带 Profile 的文件** `./config/application.yml` → `./application.yml`
3. **jar 包内、带 Profile 的文件** `classpath:/application-dev.yml`
4. **jar 包内、不带 Profile 的文件** `classpath:/application.yml`

> **这个顺序的实际用法**
>
> 正因为**包外文件优先级高于包内**，部署时可以在 jar 旁边放一个 `config/application-prod.yml` 覆盖打包进去的配置 —— 数据库密码这类敏感信息就不必打进制品。这也是官方推荐的“同一份制品部署到多个环境”的做法。

### 1.3 占位符、随机值与引用

`application.yml`

```yaml
app:
  # 引用其他配置项
  name: resource-hub
  description: ${app.name} —— 教学资源分享平台

  # 带默认值的引用：找不到就用冒号后面的值
  upload-dir: ${UPLOAD_DIR:./storage}

  # 环境变量优先，缺失时回落
  db-url: ${DATABASE_URL:jdbc:h2:mem:resourcehub}

  # 随机值：只在启动时生成一次
  instance-id: ${random.uuid}
  instance-port: ${random.int(10000,20000)}
```

随机值在**需要多个实例互不冲突的场景**（如节点标识、测试端口）很实用。注意它的作用域：同一个属性名在同一个应用里只会生成一次。

### 1.4 spring.config.import：拆分与引入

配置项变多之后，把配置按用途拆成多个文件更易维护：

`application.yml`

```yaml
spring:
  config:
    import:
      - classpath:config/datasource.yml
      - classpath:config/cache.yml
      - optional:file:./local-overrides.yml   # optional: 前缀表示文件不存在也不报错
```

> **被导入的文件优先级更高**
>
> `spring.config.import` 导入的配置**优先级高于导入它的那个文件**，这点与直觉相反，配置没生效时要留意。另外 `optional:` 前缀很重要 —— 不加的话，文件缺失会直接导致启动失败。
