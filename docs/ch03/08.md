# 八、任务执行与调度

### 8.1 异步执行

**启用异步 + 自定义线程池**

```java
@Configuration
@EnableAsync
public class AsyncConfig implements AsyncConfigurer {

    @Override
    public Executor getAsyncExecutor() {
        ThreadPoolTaskExecutor executor = new ThreadPoolTaskExecutor();
        executor.setCorePoolSize(4);
        executor.setMaxPoolSize(16);
        executor.setQueueCapacity(200);
        executor.setThreadNamePrefix("app-async-");
        // 队列满时由调用线程执行，起到背压作用，避免任务被静默丢弃
        executor.setRejectedExecutionHandler(new ThreadPoolExecutor.CallerRunsPolicy());
        executor.initialize();
        return executor;
    }
}
```

**使用**

```java
@Async
public void sendNotification(Long resourceId) {
    // 邮件、消息推送这类操作放到异步线程
}
```

> **默认线程池的坑**
>
> 不自定义线程池时，Spring 用的是 `SimpleAsyncTaskExecutor` —— 它**不复用线程**，每次调用都新建一个。任务稍微多一点就会把线程数打爆。生产项目请务必自己配一个 `ThreadPoolTaskExecutor`。

### 8.2 定时任务

**定时清理过期资源**

```java
@Component
public class CleanupTask {

    private static final Logger log = LoggerFactory.getLogger(CleanupTask.class);

    /** 每天凌晨 2 点执行 */
    @Scheduled(cron = "0 0 2 * * ?")
    public void cleanupExpiredResources() {
        log.info("开始清理过期资源");
        // ...
    }

    /** 应用启动后延迟 10 秒开始，之后每 5 分钟执行一次 */
    @Scheduled(initialDelay = 10_000, fixedRate = 300_000)
    public void refreshStatistics() {
        // ...
    }
}
```

需要在启动类或配置类上加 `@EnableScheduling`。

| 写法 | 含义 | 注意 |
| --- | --- | --- |
| `fixedRate` | 按固定频率触发，从前一次**开始**时间算 | 任务执行时间超过间隔时会堆积 |
| `fixedDelay` | 固定延迟，从前一次**结束**时间算 | 通常更安全，不会堆积 |
| `cron` | 按表达式触发 | `0 0 2 * * ?` 表示每天 2 点 |

> **多实例部署时的重复执行问题**
>
> 定时任务在**每个实例上都会执行**。应用部署三个副本，清理任务就会同时跑三次。解决办法：用分布式锁（Redis / 数据库）保证只有一个实例执行，或把定时任务抽成独立的调度服务。单机部署时不用管，但要知道这个前提。
