# 三、Profiles：多环境隔离

### 3.1 按环境拆文件

**配置文件组织**

```bash
src/main/resources/
├── application.yml              公共配置，所有环境共享
├── application-dev.yml          开发环境
├── application-test.yml         测试环境
└── application-prod.yml         生产环境
```

`application.yml（公共部分）`

```yaml
spring:
  application:
    name: resource-hub

server:
  port: 8080
  shutdown: graceful
```

`application-dev.yml`

```yaml
spring:
  datasource:
    url: jdbc:h2:mem:resourcehub;DB_CLOSE_DELAY=-1;MODE=MySQL
  jpa:
    show-sql: true

logging:
  level:
    com.example.resourcehub: debug
```

`application-prod.yml`

```yaml
spring:
  datasource:
    url: ${DB_URL}
    username: ${DB_USERNAME}
    password: ${DB_PASSWORD}
    hikari:
      maximum-pool-size: 20

logging:
  level:
    root: warn
  file:
    name: /var/log/resource-hub/app.log
```

> **生产配置不要写死密码**
>
> 上面用 `${DB_PASSWORD}` 这类占位符，实际值通过环境变量或外置配置文件注入。把密码写进 `application-prod.yml` 再打进 jar，等于把密码随制品一起分发出去 —— 这在安全审计里是明确的扣分项。更严格的做法是接入配置中心或密钥管理服务。

### 3.2 四种激活方式

| 方式 | 写法 | 适用场景 |
| --- | --- | --- |
| 配置文件 | `spring.profiles.active: dev` | 本地开发固定默认值 |
| 命令行 | `java -jar app.jar --spring.profiles.active=prod` | 部署脚本、临时切换 |
| 环境变量 | `SPRING_PROFILES_ACTIVE=prod` | 容器编排（Docker / K8s） |
| 代码 | `SpringApplication.setAdditionalProfiles("dev")` | 测试工具类 |

启动日志会明确告诉你当前激活了哪个：

```text
INFO --- c.e.resourcehub.ResourceHubApplication : No active profile set, falling back to 1 default profile: "default"
```

> **排查配置问题先看这一行**
>
> “配置改了没生效”十有八九是 Profile 没激活对。看到 `"default"` 就说明 `application-dev.yml` 等文件根本没被加载 —— 因为你激活的是 `default`，而不是 `dev`。

### 3.3 Profile 分组与组合

`application.yml`

```yaml
spring:
  profiles:
    # 激活 prod 时，同时激活下面两个
    group:
      prod: "prod-db,prod-cache"
    # 无条件引入的配置片段
    include:
      - common
```

分组让“激活一个 Profile”等于“激活一组 Profile”，适合生产环境同时开启数据库、缓存、监控等多个配置片段的场景。

### 3.4 用 @Profile 控制 Bean 的注册

**按环境切换实现**

```java
public interface FileStorage {
    String store(String filename);
}

@Repository
@Profile("dev")
class LocalFileStorage implements FileStorage {
    // 开发环境存本地磁盘
}

@Repository
@Profile("prod")
class OssFileStorage implements FileStorage {
    // 生产环境存对象存储
}
```

两个实现都标注了 `@Profile`，同一时刻只有一个生效，因此不会出现第 2 篇讲过的“同类型多个 Bean”问题。
