# 四、日志

### 4.1 默认行为已经够用

Spring Boot 默认使用 Logback，输出到控制台，默认级别 INFO，日志格式包含时间、级别、进程号、应用名、线程名、类名。你在前面章节看到的所有日志都是默认配置的输出，没有任何额外设置。

### 4.2 调整级别

`application.yml`

```yaml
logging:
  level:
    root: info
    com.example.activity: debug      # 只给自己的包开 debug
    org.hibernate.SQL: debug            # 打印实际执行的 SQL
    org.hibernate.orm.jdbc.bind: trace  # 打印 SQL 参数绑定值
```

案例工程把这两行注释掉了，需要看 SQL 时再打开：

`activity-server 的 application.yml（节选）`

```yaml
logging:
  level:
    root: info
    com.example.activity: debug
    # 想看实际发出的 SQL 就打开这两行
    # org.hibernate.SQL: debug
    # org.hibernate.orm.jdbc.bind: trace
```

> **注意 Hibernate 7 的日志类名变了**
>
> 参数绑定的日志类别是 `org.hibernate.orm.jdbc.bind`，而 5.x 时代是 `org.hibernate.type.descriptor.sql`。照抄老教程的日志配置，会出现“SQL 打得出来、参数打不出来”的情况。

### 4.3 日志分组

几个相关的包要一起调级别时，用分组更省事：

`application.yml`

```yaml
logging:
  group:
    myapp: com.example.activity.controller,com.example.activity.service
    hibernate: org.hibernate.orm.core,org.hibernate.orm.jdbc
  level:
    myapp: debug
    hibernate: info
```

### 4.4 输出到文件与滚动

`application.yml`

```yaml
logging:
  file:
    name: /var/log/activity-server/app.log
  logback:
    rollingpolicy:
      max-file-size: 50MB          # 单个文件上限
      max-history: 30              # 保留 30 天
      total-size-cap: 2GB          # 全部日志文件总上限
```

> **生产环境务必设这三个上限**
>
> 只配 `file.name` 而不限制大小和历史，服务器磁盘迟早被日志写满 —— 这是很常见的线上故障。三个参数各管一件事，建议一起配上。

### 4.5 结构化日志

日志要接入 ELK、Loki 这类平台时，JSON 格式比纯文本好解析得多：

`application.yml`

```yaml
logging:
  structured:
    format:
      console: ecs        # 或 logstash、gelf
```

开启后每条日志变成一行 JSON，字段包含时间戳、级别、logger、消息、线程等，采集端不需要写正则表达式去解析。

### 4.6 自定义 Logback 配置

需要更精细的控制（多个 appender、按业务分文件、自定义格式）时，用 `logback-spring.xml`：

`src/main/resources/logback-spring.xml`

```xml
<?xml version="1.0" encoding="UTF-8"?>
<configuration>
    <!-- 引入官方的模式与转换器，${LOG_CORRELATION_PATTERN} 才有定义 -->
    <include resource="org/springframework/boot/logging/logback/defaults.xml"/>

    <property name="APP_PATTERN"
              value="%d{yyyy-MM-dd HH:mm:ss.SSS} [%thread] %-5level %logger{36} ${LOG_CORRELATION_PATTERN:-} - %msg%n"/>

    <appender name="CONSOLE" class="ch.qos.logback.core.ConsoleAppender">
        <encoder>
            <pattern>${APP_PATTERN}</pattern>
            <charset>UTF-8</charset>
        </encoder>
    </appender>

    <appender name="FILE" class="ch.qos.logback.core.rolling.RollingFileAppender">
        <file>${LOG_PATH:-logs}/app.log</file>
        <rollingPolicy class="ch.qos.logback.core.rolling.SizeAndTimeBasedRollingPolicy">
            <fileNamePattern>${LOG_PATH:-logs}/app.%d{yyyy-MM-dd}.%i.log.gz</fileNamePattern>
            <maxFileSize>50MB</maxFileSize>
            <maxHistory>30</maxHistory>
            <totalSizeCap>2GB</totalSizeCap>
        </rollingPolicy>
        <encoder>
            <pattern>${APP_PATTERN}</pattern>
            <charset>UTF-8</charset>
        </encoder>
    </appender>

    <!-- 生产环境：控制台和文件都输出 -->
    <springProfile name="prod">
        <root level="INFO">
            <appender-ref ref="CONSOLE"/>
            <appender-ref ref="FILE"/>
        </root>
    </springProfile>

    <!-- 其余情况，含没有激活任何 profile 的时候 -->
    <springProfile name="!prod">
        <root level="INFO">
            <appender-ref ref="CONSOLE"/>
        </root>
    </springProfile>
</configuration>
```

> **profile 分支要盖住没有 profile 的情况**
>
> 直接 `mvn spring-boot:run` 启动时没有激活任何 profile，默认的 profile 名是 `default`。只写 `dev` / `prod` 两个分支的话，两个 `<root>` 都不会生效，appender 一个也挂不上去：应用照常启动、进程也在跑，但控制台里除了一行 banner 和一行 `No appenders present in context [default]` 之外什么都没有，很容易误判成启动失败。补一个 `name="!prod"` 或 `name="dev | default"` 的分支，也可以让基础 `<root>` 先挂上默认 appender，再由 profile 追加。

> **文件名必须是 logback-spring.xml，不是 logback.xml**
>
> 用 `logback.xml` 时 Logback 会在 Spring 启动**之前**加载它，此时 `<springProfile>` 和 `<springProperty>` 这些扩展标签不可用（因为还不认识它们）。Logback 会报一行 `Ignoring unknown property [springProfile]`，然后把整段分支丢掉，结果和上面说的“一个 appender 都没有”一样。要享受 Spring 的扩展能力，必须用 `logback-spring.xml`。
>
> 方向也不能反：`<springProfile>` 只能作为 `<configuration>` 的直接子元素，塞进 `<appender>` / `<logger>` / `<root>` 内部会在启动时报 `<springProfile> elements cannot be nested within an <appender>, <logger> or <root> element`。

> **`%X{traceId}` 要等接入链路追踪之后才有值**
>
> MDC 里的 `traceId` 由 Micrometer Tracing 写入。工程里没引入 `micrometer-tracing` 时这个占位符恒为空，每条日志都会多出一对空方括号，形如 `ActivityServerApplication [] - Starting ...`。Boot 4 自带的模式用的是 `${LOG_CORRELATION_PATTERN:-}`，它由 `logging.pattern.correlation` 控制，没配的时候展开成空字符串，不会留下多余符号；只需要一个占位时也可以写 `%X{traceId:-}`。

顺带一提，logback 里写的级别不是最终结果。`application.yml` 里的 `logging.level.*` 在 logback 配置之后应用，优先级更高 —— 案例工程给 `com.example.activity` 开了 `debug`，即使 logback 的 root 是 `INFO`，这个包下的 DEBUG 日志照样打得出来。
