# 七、发送邮件

### 7.1 最小配置

```xml
<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-mail</artifactId>
</dependency>
```

配置齐了就会自动装配一个 `JavaMailSender`：

```yaml
spring:
  mail:
    host: smtp.example.com
    port: 587
    username: ${MAIL_USERNAME}
    password: ${MAIL_PASSWORD}
    properties:
      mail.smtp.auth: true
      mail.smtp.starttls.enable: true
```

**`spring.mail.host` 是触发的关键。** 官方说明：只有当它存在、且 `spring-boot-starter-mail` 的相关库在类路径上时，才会创建 `JavaMailSender`。少一行 host，注入 `JavaMailSender` 就会失败。

### 7.2 超时必须设——官方专门提醒

这一条在官方文档里是加粗强调的，原文：

> In particular, certain default timeout values are infinite, and you may want to change that to avoid having a thread blocked by an unresponsive mail server.

（特别是某些默认超时值是无限的，你需要改掉它，以免线程被一个无响应的邮件服务器卡住。）

官方给的配置：

```yaml
spring:
  mail:
    properties:
      mail.smtp.connectiontimeout: 5000
      mail.smtp.timeout: 3000
      mail.smtp.writetimeout: 5000
```

三个值缺一不可，含义分别是：

| 属性 | 卡在哪一步 |
| --- | --- |
| `connectiontimeout` | 建立到 SMTP 服务器的连接 |
| `timeout` | 等待服务器响应 |
| `writetimeout` | 写入数据 |

**最危险的地方在于“邮件发不出去”通常不是核心业务。** 注册成功后发一封欢迎邮件，邮件服务挂了不该让注册失败。所以调用点必须包 try-catch，并且不要在事务里发——发邮件是毫秒级的操作，慢起来能到几十秒，占着事务不放会把数据库连接池拖垮。

### 7.3 JNDI 与模板

容器环境里邮件会话可能由应用服务器管，用 `spring.mail.jndi-name` 引用现成的：

```yaml
spring:
  mail:
    jndi-name: mail/Session
```

官方明确说明：**设了 `jndi-name` 后，它会覆盖其他所有 Session 相关设置**。两者不要同时配，否则会有“为什么我改的配置不生效”的困惑。

邮件正文用模板拼装比字符串拼接好维护，Thymeleaf 是常见选择。但模板引擎不是发送邮件必需的，简单场景直接拼 HTML 就够了。
