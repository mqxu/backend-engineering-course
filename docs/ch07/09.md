# 九、常见问题速查表

| 症状 | 原因与解法 |
| --- | --- |
| 注解都写了但缓存不生效 | `@EnableCaching` 漏了；或方法被自调用绕过了代理（2.10） |
| 启动报 `No qualifying bean of type 'RestClient$Builder'` | 缺 `spring-boot-restclient` 依赖（4.3，Boot 4 已从 autoconfigure 拆出） |
| 缓存名写错，但没有报错 | Caffeine 按需创建不报错；配了 `cache-names` 时用未声明的名字才会失败（2.5） |
| 改了数据但页面还是旧值 | 写方法漏 `@CacheEvict`；或 `cacheNames` / `key` 不匹配（2.12 的排查顺序） |
| 缓存条目只增不减 | 用了 simple provider，或者 Caffeine 的 `spec` 里没写 `maximumSize`（2.2） |
| 缓存里存的是实体，出现奇怪的不一致 | 缓存值应该是不可变 DTO，不是 JPA 实体（2.8） |
| 多实例部署时数据不一致 | 本地缓存跨实例不共享，需要 Redis（2.11） |
| `@RequestParam` 上的 `@Min` 不生效 | 控制器类上缺 `@Validated`（3.2） |
| 校验错误只报第一个字段 | 全局异常处理器里没用 `getFieldErrors()` 全量收集（3.4） |
| 校验消息返回了 `{xxx}` 原文 | 消息 key 在 `messages.properties` 里找不到（3.9） |
| 自定义约束把“必填”也管了 | `isValid` 里 `null` 应当直接返回 `true`（3.6） |
| 配置配错但启动没报错 | 配置类缺 `@Validated`；光写约束注解不生效（3.8） |
| `read-timeout=3` 导致所有请求超时 | Duration 裸数字按**毫秒**解析，必须带单位（第五节） |
| 外部接口超时变成 500 | 没有单独 catch `ResourceAccessException`，应该转 502（4.6） |
| 想缓存列表接口但命中率极低 | 参数组合发散，不该缓存（2.6） |
| 定时任务“到点了没执行” | `TaskScheduler` 默认单线程，被前面的任务占住了（6.1） |
| 定时任务执行时间飘忽 | 用了 `fixedRate`，改成 `fixedDelay`（6.2） |
| 集群里同一个任务跑了三次 | `@Scheduled` 每实例各跑一份，需要分布式锁或 Quartz（6.4） |
| `@Scheduled` 方法里的缓存注解不生效 | 自调用绕过代理（6.5） |
| 邮件发送把线程卡死 | SMTP 超时默认是无限的，三个 timeout 都要设（7.2） |
| 重启后 Quartz 的触发器全没了 | `initialize-schema: always` 的标准脚本会删表，生产要改 `never`（第八节） |

> **下一篇要做什么**
>
> 到这里，单体的读、写、缓存、外部依赖都讲完了。第 8 篇处理“服务之间怎么对话”：用 Kafka 做异步事件、用 AMQP 做任务分发、用 WebSocket 做服务端推送。同样会延续本篇的做法——每个概念都落到案例工程里能跑起来，实测结果说话。
