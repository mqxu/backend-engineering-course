# 一、官方 IO 一章覆盖了什么

官方的 IO 章节标题是 "IO"，字面看像是文件读写，实际是个杂物间，收的都是“应用与外部活动交互”的技术：

| 官方小节 | 讲什么 | 本篇处理方式 |
| --- | --- | --- |
| 缓存 | `@Cacheable` 抽象、八种缓存实现 | 第二节，含实测 |
| 校验 | Bean Validation、方法级校验 | 第三节，含实测 |
| REST Client | `RestClient`、`RestTemplate`、底层 HTTP 库 | 第四节，含实测 |
| 邮件 | `JavaMailSender` | 第七节，只讲配置要点 |
| Quartz | 需要持久化的定时任务 | 第八节，只讲与 `@Scheduled` 的分工 |
| Batch / gRPC / Web Services / JMS | 各技术栈集成的入口 | 提及不展开 |

任务调度不在 IO 章下，而是放在 Features 章，本篇第六节一并讲完——它和缓存有很自然的配合场景。

### 1.1 本篇在案例工程里加了什么

第 6 篇结束时 `activity-server` 有 42 个测试。本篇新增的代码集中在下面六个文件：

| 新增文件 | 作用 |
| --- | --- |
| `config/CacheConfig.java` | 只挂一个 `@EnableCaching` |
| `config/RestClientConfig.java` | 构建调用外部目录服务的 `RestClient` |
| `config/ExternalApiProperties.java` | 外部服务的地址与超时配置，带启动期校验 |
| `config/SchedulingConfig.java` | 只挂一个 `@EnableScheduling` |
| `service/ExternalCatalogService.java` | 调用外部接口，演示三类失败的处理 |
| `service/CacheWarmupJob.java` | 定时清理场地缓存 |

最终测试数从 42 增加到 **58**，全部通过。
