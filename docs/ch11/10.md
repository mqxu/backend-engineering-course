# 11.10 问题速查

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| `java -jar` 报“没有主清单属性” | 拿到的是 `.jar.original` | 检查 jar 的 MANIFEST 里有没有 `Spring-Boot-Version` |
| `-Djarmode=layertools` 报 jarmode 不认识 | 4.x 已改名 | 换成 `-Djarmode=tools` |
| `extract` 出的 `spring-boot-loader` 是空目录 | `--layers` 默认不带启动器 | 需要启动器时加 `--launcher` |
| 解压后 `java -jar` 报找不到类 | 各层没拼到同一个目录 | 把四层内容都拷进同一工作目录 |
| 薄 jar 的 `Class-Path` 指向的 lib 找不到 | 同上，`lib/` 必须与 jar 同级 | 检查目录结构 |
| `.jsa` 挂上去启动没变化 | 用的是可执行 jar | CDS 只对解压形态生效 |
| `.jsa` 拷到别的机器上报错 | 归档与平台、JDK 版本绑定 | 在目标平台重新做训练运行 |
| 镜像比预期大 60 多 MB | `COPY` 之后又用了 `RUN chown` | 改成 `COPY --chown` |
| 训练运行让镜像多出上百 MB | CDS 归档本身就有 100MB 量级 | 评估启动收益是否值得这个体积 |
| 非 root 用户启动后写文件失败 | 工作目录或子目录属主是 root | 建目录时一并 `chown`，或把可变数据挂卷 |
| `chown` 之后文件属主还是 root | 写在了 `COPY` 之前 | `COPY --chown` 必须和 `COPY` 在同一条指令里 |
| 源码没变但镜像每次都要重建 | jar 的时间戳变了 | 分层写法可让依赖层命中缓存；必要时 `--no-cache` |
| `-Dspring.aot.enabled=true` 后启动失败 | 用了 AOT 不支持的运行期条件装配 | 检查 `@ConditionalOnProperty` 与 profile 相关 Bean |
| 打了 `-Pnative` 但没变快 | 只跑了 `package`，AOT 代码没被启用 | 运行时加 `-Dspring.aot.enabled=true` |
| `mvn -Pnative package` 没产出可执行文件 | `native:compile` 不绑定在 `package` 阶段 | 显式加上 `native:compile` |
| 原生编译报缺少反射配置 | `--no-fallback` 加提示文件不全 | 补 `@RegisterReflectionForBinding` 或自定义 hint |
| 原生镜像里 profile 不生效 | 封闭世界假设，Bean 定义构建期定死 | 改成用配置值区分，而不是用 profile 区分装配 |
| 容器堆内存只有限制的 1/4 | `MaxRAMPercentage` 默认 25% | `JAVA_TOOL_OPTIONS=-XX:MaxRAMPercentage=75` |
| 改了环境变量配置没生效 | 名字没规范化 | 点转下划线、去掉连字符、全大写 |
| `docker stop` 时请求被切断 | 没开优雅停机 | `server.shutdown=graceful` |
| buildpacks 构建报 builder 不可信 | 用了非官方 builder | 显式设 `trustBuilder`，或改用官方 builder |
