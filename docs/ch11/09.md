# 11.9 从“能跑”到“能在生产上跑”

镜像能起来只是最低要求。下面这些是上线前必须处理掉的。

### 配置不要烤进镜像

理想状态是**同一份镜像可以部署到任何环境**。把环境相关的配置写进镜像，就变成每个环境都要单独构建一次。

Spring Boot 的外部化配置让这件事很好做，因为环境变量会被规范化后匹配到配置项。官方给的反向规则是：点转下划线、去掉连字符、转大写。比如 `spring.main.log-startup-info` 对应 `SPRING_MAIN_LOGSTARTUPINFO`。实测这几种写法都能覆盖 `server.port`：

```text
无覆盖                                   -> Tomcat started on port 8080
SERVER_PORT=9999                         -> Tomcat started on port 9999
SERVER__PORT=9998                        -> Tomcat started on port 9998
SPRING_PROFILES_ACTIVE=prod + 端口覆盖    -> The following 1 profile is active: "prod"
```

注意最后一行：环境变量能同时覆盖端口和激活 profile，镜像本身不用改任何东西。部署命令就是把这些值传进去：

```shell
$ docker run -d -p 8080:8080 \
    -e SPRING_PROFILES_ACTIVE=prod \
    -e SPRING_DATASOURCE_URL=jdbc:mysql://db:3306/activity \
    activity-server:1.0.0
```

第 3 篇讲过配置的优先级顺序，环境变量排在命令行参数之后、`application-{profile}.yml` 之前，正好适合放“部署时才知道”的值。

### 内存参数：容器感知默认是开的

Java 10 之后 JVM 默认开启容器感知。实测一个限制 512MB 的容器：

```text
$ docker run --rm --memory=512m --entrypoint java activity-server:layered \
      -XX:+PrintFlagsFinal -version
   size_t MaxHeapSize              = 134217728    {product} {ergonomic}   # 128 MB
     bool UseContainerSupport      = true         {product} {default}
```

`MaxHeapSize` 是 128MB，正好是 512MB 的 25%——这就是 `MaxRAMPercentage` 的默认值。堆之外还有元空间、线程栈、直接内存、JIT 代码缓存要占地方，25% 对多数应用偏保守。

调整不用改 Dockerfile，`JAVA_TOOL_OPTIONS` 这个环境变量 JVM 自己会读：

```shell
$ docker run --memory=512m -e JAVA_TOOL_OPTIONS="-XX:MaxRAMPercentage=75" ...
```

```text
Picked up JAVA_TOOL_OPTIONS: -XX:MaxRAMPercentage=75
   size_t MaxHeapSize              = 402653184    {product} {ergonomic}   # 384 MB
```

`Picked up JAVA_TOOL_OPTIONS` 这行会打在标准错误上，它不是报错，只是提示。

反过来也要留意：**如果容器没有设置内存上限，`MaxRAMPercentage` 会按宿主机内存算**，可能开出一个远超预期的大堆。给容器设内存上限本身就是必要的。

### 优雅停机

容器停止时运行时发的是 SIGTERM，应用需要在收到信号后停止接收新请求、把正在处理的请求做完。这个开关第 4 篇配过，容器场景下是必需品：

```yaml
server:
  shutdown: graceful

spring:
  lifecycle:
    timeout-per-shutdown-phase: 20s
```

生效时日志里能看到这段：

```text
Commencing graceful shutdown. Waiting for active requests to complete
Graceful shutdown complete
```

`timeout-per-shutdown-phase` 是兜底——等待超过这个时间就强制退出，避免一个卡住的请求把停机流程拖住。

### 日志走标准输出

容器里的日志应该走 stdout/stderr，由容器运行时收集。Spring Boot 默认就是 console 输出，不需要配。

两条注意：

`logging.file.name` 不要配。镜像层是只读的，写在容器文件系统里的日志随容器销毁一起消失，容器运行时也收集不到。

日志级别可以用环境变量调（`LOGGING_LEVEL_COM_EXAMPLE_RESOURCEHUB=DEBUG`），第 10 篇讲的 `loggers` 端点则能在不重启的情况下改，两者配合足够应付线上的排查需求。

### 密钥不进镜像

镜像会被推到仓库、会被拉下来、会被别人用 `docker history` 逐层看到。写在 Dockerfile 的 `ENV` 里的东西不是秘密——**`ENV` 的内容会进入镜像元数据**。

密钥通过 `-e`、`--env-file` 传，或者挂载密钥文件、接入密钥管理服务。这一条没有例外。

### 时区

容器默认时区是 UTC。业务里有日期格式化、或者需要日志时间和业务时间对齐时，显式指定：

```shell
$ docker run -e TZ=Asia/Shanghai ...
```
