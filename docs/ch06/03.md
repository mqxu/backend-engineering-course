# 三、SQL 初始化：schema.sql 与 data.sql

### 3.1 默认规则

Spring Boot 在类路径根目录下自动识别这几个文件：

| 文件 | 默认位置 | 作用 |
| --- | --- | --- |
| `schema.sql` | `optional:classpath*:schema.sql` | 建表 |
| `data.sql` | `optional:classpath*:data.sql` | 灌数据 |
| `schema-${platform}.sql` | 平台专属建表 | `${platform}` 取自 `spring.sql.init.platform` |
| `data-${platform}.sql` | 平台专属数据 | 同上 |

三条规则必须记住：

1. **`optional:` 前缀意味着文件不存在也不报错**。想让缺文件直接启动失败，把这个前缀去掉。
2. **默认只对嵌入式内存数据库执行**（`spring.sql.init.mode` 默认 `embedded`）。连 MySQL 时不写脚本进去，这是刻意的保护。
3. **脚本默认在 JPA 的 `EntityManagerFactory` 创建之前执行**——这一点直接引出下一个坑。

### 3.2 为什么必须加 defer-datasource-initialization

JPA 项目里，如果让 Hibernate 负责建表（`ddl-auto`），而 `data.sql` 又先于建表执行，插入语句会报“表不存在”。本项目的解法：

```yaml
spring:
  jpa:
    hibernate:
      ddl-auto: create-drop
    # 让 data.sql 在 Hibernate 建表之后执行
    defer-datasource-initialization: true
  sql:
    init:
      mode: always
```

`defer-datasource-initialization: true` 的作用就是把 `DataSource` 初始化推迟到所有 `EntityManagerFactory` 创建完成之后。官方对这个开关的态度是**有条件推荐**：它本来是为了照顾“想用脚本补充 Hibernate 建出来的表”这种需求，属于混合方案。

### 3.3 spring.sql.init.* 全量属性

| 属性 | 取值 | 说明 |
| --- | --- | --- |
| `spring.sql.init.mode` | `embedded`（默认）/ `always` / `never` | 何时执行脚本 |
| `spring.sql.init.schema-locations` | 路径列表 | 替换默认的 `schema.sql` |
| `spring.sql.init.data-locations` | 路径列表 | 替换默认的 `data.sql` |
| `spring.sql.init.platform` | 字符串 | 拼出 `schema-${platform}.sql`，常填数据库厂商名 |
| `spring.sql.init.continue-on-error` | `true` / `false`（默认） | 默认遇到错误即失败；设 `true` 可跳过出错语句 |
| `spring.sql.init.encoding` | 字符集 | 脚本编码 |
| `spring.sql.init.separator` | 分隔符 | 语句分隔符，默认 `;` |

MyBatis-Plus 工程就得靠它显式指定脚本位置——因为 MyBatis-Plus 不会建表：

```yaml
spring:
  sql:
    init:
      mode: always
      schema-locations: classpath:schema.sql
      data-locations: classpath:data.sql
```

> **脚本注释只支持两种写法**
>
> 初始化脚本里只能用 `--` 行注释和 `/* */` 块注释。用 `#` 开头会当成 SQL 内容发出，直接报语法错误。

### 3.4 版本化迁移：Flyway 与 Liquibase

`schema.sql` 适合教学和演示，**不适合生产**：它没有版本概念，改一次表结构就得靠人肉记住哪些环境已经执行过。生产环境用迁移工具，Spring Boot 内置对接了两个（版本由官方 BOM 管理）：

| 工具 | BOM 版本 | 脚本位置 | 特点 |
| --- | --- | --- | --- |
| Flyway | 12.4.0 | `classpath:db/migration` | 脚本名 `V1__init.sql`，SQL 为主，上手快 |
| Liquibase | 5.0.3 | `classpath:db/changelog` | XML / YAML / SQL 均可，抽象的 changeset 概念，支持回滚 |

两者都是“引依赖即生效”：把 `flyway-core` 放进 `pom.xml`，Spring Boot 在启动时自动执行迁移，并把执行记录写进 `flyway_schema_history` 表。配合上要注意一条：

```yaml
spring:
  jpa:
    hibernate:
      ddl-auto: validate
```

**用迁移工具管表结构时，`ddl-auto` 必须改成 `validate`**（让 Hibernate 只校验实体与表是否一致，不动表结构），否则框架和迁移工具会互相打架。

### 3.5 不要混用两套初始化机制

官方文档对这一条用了明确的措辞：如果使用 Flyway 或 Liquibase，就应该**单独使用它们**来创建和初始化 schema；把基础的 `schema.sql` / `data.sql` 与迁移工具并用是不推荐的，而且**该支持将在未来版本中被移除**。

所以正确的组合只有两种：

| 场景 | 表结构 | 初始数据 |
| --- | --- | --- |
| 教学 / 演示 | `ddl-auto: create-drop` | `data.sql` |
| 生产 | Flyway / Liquibase | Flyway / Liquibase |

### 3.6 Hibernate 的 import.sql

还有个容易混淆的文件：类路径根目录下的 `import.sql`。它在 `ddl-auto` 为 `create` 或 `create-drop` 时由 **Hibernate 自己**执行——和 Spring 的 `data.sql` 是两套机制。本教程不用它，见到时知道它是 Hibernate 的特性即可。
