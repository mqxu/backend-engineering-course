# 四、JPA 之前：JdbcTemplate 与 JdbcClient

不是所有数据访问都值得上 ORM。官方给了三个层次的工具：

| 工具 | 定位 | 适用 |
| --- | --- | --- |
| `JdbcClient` | 官方在 6.1 引入的现代写法，链式 API | 优先选它写手写 SQL |
| `JdbcTemplate` | 经典方案，依然是底层实现 | 老代码、需要精细控制时 |
| 裸 JDBC | 手动管理 `Connection` | 基本不用 |

`JdbcClient` 由自动配置直接提供，注入即用：

```java
@Service
public class StatsService {

    private final JdbcClient jdbcClient;

    public StatsService(JdbcClient jdbcClient) {
        this.jdbcClient = jdbcClient;
    }

    /** 统计每个分类下的资源数量 */
    public List<CategoryStat> countByCategory() {
        return jdbcClient.sql("""
                        SELECT c.name AS name, COUNT(r.id) AS total
                          FROM category c
                          LEFT JOIN resource_item r ON r.category_id = c.id AND r.enabled = true
                         GROUP BY c.name
                         ORDER BY total DESC
                        """)
                .query((rs, rowNum) -> new CategoryStat(rs.getString("name"), rs.getLong("total")))
                .list();
    }
}
```

几个用法要点：

- `sql(...)` 里用 `:name` 写命名参数，再 `.param("name", value)` 绑定，比 `?` 占位符可读。
- 需要单条记录用 `.query(...).optional()` 或 `.single()`，后者查不到会抛异常。
- `spring.jdbc.template.*` 的属性（例如 `spring.jdbc.template.max-rows: 500`）对 `JdbcClient` 同样生效，因为它是基于同一个 `JdbcTemplate` 构建的。

**什么时候该用手写 SQL 而不是 JPA**：多表聚合统计、复杂的批量更新、需要用数据库特有语法的场景。ORM 擅长的是对象到表的映射，不擅长报表查询。
