# 一、先确认你在用哪个版本

“最新版本是多少”这个问题，靠博客和搜索引擎得到的答案经常是过时的。可靠的做法只有三个：查 Maven 中央仓库的元数据、看官方文档站、看本地实际依赖。

### 方法一：查 Maven 中央仓库（最可靠）

Maven 中央仓库为每个构件维护一个 `maven-metadata.xml`，里面有 `<latest>` 与 `<release>` 两个字段。以 `spring-boot-starter-parent` 为例：

```bash
curl -s https://repo1.maven.org/maven2/org/springframework/boot/spring-boot-starter-parent/maven-metadata.xml \
  | grep -oE '<(latest|release)>[^<]*'
```

本机实际执行的结果：

```text
latest>4.2.0-M1
release>4.2.0-M1

# 最近若干个版本号
4.1.0-M1
4.1.0-M2
4.1.0-M3
4.1.0-M4
4.1.0-RC1
4.1.0
4.1.1
4.2.0-M1
```

> **这里有个坑，很多人被它误导**
>
> `<release>` 字段**并不代表稳定版**，它只表示“最新发布的版本”，里程碑版（`-M1`）和候选版（`-RC1`）同样会被写进去。所以上例中 `<release>` 是 `4.2.0-M1`，但当前**稳定版（GA）是 4.1.1**。
>
> 判断法则很简单：**版本号里不带 `-M`、`-RC`、`-SNAPSHOT` 后缀的才是 GA**。生产项目请用 GA 版本；里程碑版适合提前体验新特性，不建议上生产。

### 方法二：看本地实际生效的版本

工程建起来之后，判断“我到底在用哪个版本”最直接的办法是看启动日志和依赖树。Spring Boot 启动时会打印一整套版本信息：

```bash
# 依赖树：看 Spring Boot 与各 starter 的实际版本
mvn dependency:tree -Dincludes=org.springframework.boot

# 启动日志：看运行期各组件版本（本机实测片段）
java -jar target/activity-server-1.0.0.jar
```

```text
  .   ____          _            __ _ _
 /\\ / ___'_ __ _ _(_)_ __  __ _ \ \ \ \
( ( )\___ | '_ | '_| | '_ \/ _` | \ \ \ \
 \\/  ___)| |_)| | | | | || (_| |  ) ) ) )
  '  |____| .__|_| |_| |_| |_\__, | / / / /
 =========|_|==============|___/=/_/_/_/

:: Spring Boot ::                (v4.1.1)

INFO --- [activity-server] : HHH000001: Hibernate ORM core version 7.4.5.Final
INFO --- [activity-server] : Tomcat started on port 8080 (http) with context path '/'
INFO --- [activity-server] : Started ActivityServerApplication in 4.069 seconds
```

启动日志里的这几行信息量很大：Spring Boot 版本、Hibernate 版本、内嵌容器与端口、启动耗时。写文档或做技术方案时，把它截图放进附件，比写“我用的是最新版”可信得多。

### 本教程的版本基线

| 项目 | 版本 | 说明 |
| --- | --- | --- |
| Spring Boot | **4.1.1** | 当前 GA，2026-08 发布 |
| 3.5 维护线 | 3.5.16 | 老项目升级过渡用，仍在维护 |
| 开发版 | 4.2.0-M1 | 里程碑版，含未稳定特性，不用于本教程 |
| JDK | 21（LTS） | 官方要求 17 及以上，兼容至 26 |
| Maven | 3.9.11 | 官方要求 3.6.3 及以上 |
