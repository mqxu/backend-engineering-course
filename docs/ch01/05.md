# 五、常见问题排查

| 症状 | 原因与解法 |
| --- | --- |
| 启动报 `Port 8080 was already in use` | 端口被占用。macOS / Linux 用 `lsof -ti:8080 \| xargs kill -9` 结束占用进程，或改 `server.port` |
| 启动报 `Web server failed to start. Port XXX was already in use`，但 `lsof` 看不到进程 | 端口处于 `TIME_WAIT`（刚被结束的进程尚未完全释放）。等几秒再启动，或直接换端口 |
| `java -jar` 报 `no main manifest attribute` | 用错了 jar。要跑的是 repackage 之后的可执行 jar，不是 `.jar.original`；或者检查 `spring-boot-maven-plugin` 是否配置好 |
| IDE 里编译通过，命令行 `mvn test` 报 JDK 版本不兼容 | Maven 用的是 `JAVA_HOME`，IDE 用的是自己配置的 SDK。执行 `mvn -v` 看 Maven 实际使用的 Java 版本，两者对齐 |
| 接口返回 404，但启动日志正常 | 控制器没被扫描到。检查控制器所在包是否在主类所在包的**同级或子级**；包结构问题看第 2 篇 |
| 中文返回乱码 | 确认 `project.build.sourceEncoding` 为 `UTF-8`；Spring Boot 4 默认响应编码已是 UTF-8，通常问题出在编译编码或终端编码上 |

> **下一篇要做什么**
>
> 现在工程能跑起来，但业务代码放哪里、为什么这么放、自动配置到底是怎么生效的，这些还没回答。下一篇对照官方的 *Structuring Your Code* 与 *Auto-configuration* 章节，把工程的骨架与运行机制彻底讲清楚，并给案例项目补齐分层结构。
