# 二、Maven 构建系统：parent、starter、plugin 三者关系

入门跑通之后，值得把构建系统的三个角色讲清楚，否则后面加依赖时很容易做出错误判断。

**parent —— 定规矩**

`spring-boot-starter-parent` 不引入任何依赖，它只做三件事：管理依赖版本、配置 Maven 插件、设置活动过滤与编码。它是“规则制定者”。

**starter —— 打包功能**

如 `spring-boot-starter-webmvc`，是一组依赖的集合。引一个 starter 等于引了一串配套的库，并且它们之间版本兼容。

**plugin —— 管构建**

`spring-boot-maven-plugin` 负责把普通 jar 重新打包成可执行 jar（`repackage`），并提供 `spring-boot:run` 命令。

### 2.1 不用 parent POM 也可以

如果项目必须继承公司自己的父 POM（很常见），就不能再用 `spring-boot-starter-parent` 了。这时用 **BOM 导入**的方式达到同样的版本管理效果：

`pom.xml（不用 parent 的写法）`

```xml
<dependencyManagement>
    <dependencies>
        <dependency>
            <groupId>org.springframework.boot</groupId>
            <artifactId>spring-boot-dependencies</artifactId>
            <version>4.1.1</version>
            <type>pom</type>
            <scope>import</scope>
        </dependency>
    </dependencies>
</dependencyManagement>

<!-- 但插件必须自己声明，因为不再有 parent 帮你绑定 repackage -->
<build>
    <plugins>
        <plugin>
            <groupId>org.springframework.boot</groupId>
            <artifactId>spring-boot-maven-plugin</artifactId>
            <version>4.1.1</version>
            <executions>
                <execution>
                    <goals>
                        <goal>repackage</goal>
                    </goals>
                </execution>
            </executions>
        </plugin>
    </plugins>
</build>
```

两者的差别很具体：用 parent 时，插件的 `repackage` 目标已经绑定好了，你不写 `<executions>` 也能打出可执行 jar；用 BOM 时必须自己写，否则打出来的 jar 无法运行 —— 这是换父 POM 时最常被忽略的一步。

### 2.2 覆盖依赖版本

父 POM 管理的版本可以覆盖，优先级从高到低：

1. **在 dependencies 里直接写版本号**

   `pom.xml`

   ```xml
   <dependency>
       <groupId>com.h2database</groupId>
       <artifactId>h2</artifactId>
       <version>2.3.232</version>   <!-- 直接指定，覆盖父 POM -->
   </dependency>
   ```
2. **用属性覆盖（推荐）** 父 POM 里的版本大多由属性驱动，重定义属性即可全局生效，且所有相关依赖版本保持一致：

   `pom.xml`

   ```xml
   <properties>
       <h2.version>2.3.232</h2.version>
   </properties>
   ```

   属性名怎么查？看 [Dependency Versions 附录](https://docs.spring.io/spring-boot/appendix/dependency-versions/properties.html)，或者直接在本地 `~/.m2/repository/org/springframework/boot/spring-boot-dependencies/4.1.1/` 下的 pom 文件里搜。

> **覆盖版本要谨慎**
>
> Spring Boot 管理的版本组合是经过测试的。随意升级其中某个库（尤其是 Spring Framework 本身、Hibernate、Jackson），很容易出现兼容问题。确实需要升级时，优先选 Spring Boot 已经发布的新版本，而不是单个库手动调版本。

### 2.3 Gradle 对照

团队用 Gradle 的话，插件与依赖写法如下（版本与 4.1.1 对应）：

`build.gradle`

```bash
plugins {
    id 'java'
    id 'org.springframework.boot' version '4.1.1'
    id 'io.spring.dependency-management' version '1.1.7'
}

group = 'com.example'
version = '0.0.1-SNAPSHOT'

java {
    toolchain {
        languageVersion = JavaLanguageVersion.of(21)
    }
}

repositories {
    mavenCentral()
}

dependencies {
    implementation 'org.springframework.boot:spring-boot-starter-webmvc'
    testImplementation 'org.springframework.boot:spring-boot-starter-webmvc-test'
}
```

常用命令对照：

| 动作 | Maven | Gradle |
| --- | --- | --- |
| 查看依赖树 | `mvn dependency:tree` | `gradle dependencies` |
| 开发期启动 | `mvn spring-boot:run` | `gradle bootRun` |
| 打包可执行 jar | `mvn package` | `gradle bootJar` |
| 跑测试 | `mvn test` | `gradle test` |
