# 一、对照官方教程：从零到 Hello World

官方入门教程（[Developing Your First Spring Boot Application](https://docs.spring.io/spring-boot/tutorial/first-application/index.html)）用不到十步就能跑起一个 Web 应用。下面是完整过程，代码与官方一致，我补充了每一步的实测输出和背后的原因。

### 1.1 前置检查

```bash
java -version
mvn -v
```

官方教程里的输出示例用的是 JDK 17，本机是 JDK 21：

```text
openjdk version "21.0.12.1" 2026-08-18 LTS
OpenJDK Runtime Environment (build 21.0.12.1+1-LTS)
OpenJDK 64-Bit Server VM (build 21.0.12.1+1-LTS, mixed mode, sharing)
```

Spring Boot 4.1 的最低要求是 JDK 17，所以 17、21、25 都能跑，教程统一用 21 LTS。

### 1.2 创建最小 pom.xml

先建一个只有父 POM 的空工程，确认构建链路通：

`pom.xml（最小版本）`

```xml
<?xml version="1.0" encoding="UTF-8"?>
<project xmlns="http://maven.apache.org/POM/4.0.0"
         xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance"
         xsi:schemaLocation="http://maven.apache.org/POM/4.0.0 https://maven.apache.org/xsd/maven-4.0.0.xsd">
    <modelVersion>4.0.0</modelVersion>

    <parent>
        <groupId>org.springframework.boot</groupId>
        <artifactId>spring-boot-starter-parent</artifactId>
        <version>4.1.1</version>
    </parent>

    <groupId>com.example</groupId>
    <artifactId>myproject</artifactId>
    <version>0.0.1-SNAPSHOT</version>
</project>
```

此时工程没有任何依赖。官方教程建议先跑一次 `mvn package` 验证构建可用，你会看到一条无害的警告：

```text
[WARNING] JAR will be empty - no content was marked for inclusion!
```

这条警告的意思是“没有源码可以打包”，属于正常现象，说明构建链路已经通了。

### 1.3 加上 Web 依赖

加依赖之前，先看一眼当前依赖树：

```bash
mvn dependency:tree
```

```text
[INFO] com.example:myproject:jar:0.0.1-SNAPSHOT
```

只有一行 —— 说明 `spring-boot-starter-parent` 本身**不引入任何依赖**，它只负责版本管理与插件配置。现在加上 Web 依赖：

`pom.xml（追加）`

```xml
    <dependencies>
        <dependency>
            <groupId>org.springframework.boot</groupId>
            <artifactId>spring-boot-starter-webmvc</artifactId>
        </dependency>
    </dependencies>
```

> **注意坐标：官方教程用的是 webmvc，不是 web**
>
> 官方 4.1.1 教程里写的是 `spring-boot-starter-webmvc`。老的 `spring-boot-starter-web` 在 4.x 已标记废弃（详见第 0 篇的改名表），虽然仍能下载使用，但新项目请直接用新坐标。这个细节是 3.x 教程与 4.x 教程最直观的分水岭。

再次查看依赖树，会看到 Tomcat 和 Spring MVC 都被带进来了：

```bash
mvn dependency:tree | head -20
```

>

> 二、**内嵌 Tomcat 是 starter 带进来的**，不需要单独引，也不需要装 Tomcat。
> 三、**日志框架也一并带进来了**（`spring-boot-starter-logging`，底层是 Logback），这也是为什么 Spring Boot 应用的日志开箱即用。

### 1.4 写代码

官方教程把主类和控制器写在同一个文件里，非常适合理解最小结构：

`src/main/java/com/example/MyApplication.java`

```java
package com.example;

import org.springframework.boot.SpringApplication;
import org.springframework.boot.autoconfigure.SpringBootApplication;
import org.springframework.web.bind.annotation.RequestMapping;
import org.springframework.web.bind.annotation.RestController;

@RestController
@SpringBootApplication
public class MyApplication {

    @RequestMapping("/")
    String home() {
        return "Hello World!";
    }

    public static void main(String[] args) {
        SpringApplication.run(MyApplication.class, args);
    }

}
```

实际项目里不会这样写 —— 主类应该单独放、控制器应该放 `web` 包（第 2 篇详述）。这里先合在一起，是为了让“一个类就构成一个 Web 应用”这件事看得更清楚。

#### 三个关键点

| 元素 | 来源 | 作用 |
| --- | --- | --- |
| `@RestController` | Spring MVC（不是 Boot 特有） | 构造型注解。告诉 Spring 这个类是处理 Web 请求的组件，且返回值直接作为响应体，不做页面渲染 |
| `@RequestMapping("/")` | Spring MVC | 路由信息。把 `/` 路径的请求映射到 `home()` 方法 |
| `@SpringBootApplication` | Spring Boot | 元注解，等价于 `@SpringBootConfiguration` + `@EnableAutoConfiguration` + `@ComponentScan` 三者叠加 |

其中 `@EnableAutoConfiguration` 是 Spring Boot 的灵魂所在。它做的事情是：**根据 classpath 上有什么，猜测你想怎么配置 Spring**。因为 `spring-boot-starter-webmvc` 带了 Tomcat 和 Spring MVC，自动配置就判断“这是要在 Web 应用里提供服务”，于是自动配好 DispatcherServlet、内嵌 Tomcat、JSON 消息转换器等一整套组件。

`main` 方法调用 `SpringApplication.run()`，把主类作为参数传进去，Spring Boot 就知道从哪里开始扫描组件、加载配置。

### 1.6 打包成可执行 jar

在 `pom.xml` 的 `dependencies` 下方加上打包插件：

`pom.xml（追加）`

```xml
    <build>
        <plugins>
            <plugin>
                <groupId>org.springframework.boot</groupId>
                <artifactId>spring-boot-maven-plugin</artifactId>
            </plugin>
        </plugins>
    </build>
```

然后打包：

```bash
mvn package
```

```text
[INFO] --- maven-jar-plugin:...:jar (default-jar) @ activity-server ---
[INFO] Building jar: target/activity-server-1.0.0.jar
[INFO] --- spring-boot-maven-plugin:4.1.1:repackage (repackage) @ activity-server ---
[INFO] Replacing main artifact with repackaged archive
[INFO] BUILD SUCCESS
```

看一下 `target` 目录：

```bash
ls -lh target/*.jar
```

```text
-rw-r--r--  1 moqi  staff   54M  Sep 13 15:25  target/activity-server-1.0.0.jar
-rw-r--r--  1 moqi  staff   7.3K Sep 13 15:25  target/activity-server-1.0.0.jar.original
```

两个文件的分工常常被误解：

| 文件 | 是什么 | 能不能运行 |
| --- | --- | --- |
| `activity-server-1.0.0.jar` | 经过 `repackage` 处理的可执行 jar，内含应用类 + 全部依赖 jar（嵌套存放） | 可以，`java -jar` 直接启动 |
| `activity-server-1.0.0.jar.original` | Maven 原本打出来的普通 jar，只有你自己的类，没有依赖 | 单独运行会报 `NoClassDefFoundError` |

> **Spring Boot 处理依赖的方式与 uber jar 不同**
>
> 把全部依赖解压后合并成一个大 jar（uber jar）会带来两个问题：看不出用了哪些库、不同 jar 里的同名文件会互相覆盖。Spring Boot 的做法是把依赖 jar **原样嵌套**放进可执行 jar 里，由自己实现的类加载器在运行时读取。所以你能用 `jar tf` 清楚地看到每个依赖：
>
> ```bash
> # 看 jar 里嵌入了哪些依赖（字母序排列）
> jar tf target/activity-server-1.0.0.jar | grep "BOOT-INF/lib/" | head -6
>
> # 数一下总共有多少个依赖 jar
> jar tf target/activity-server-1.0.0.jar | grep -c "BOOT-INF/lib/.*\.jar"
> ```
>
> ```text
> BOOT-INF/lib/
> BOOT-INF/lib/logback-classic-1.5.38.jar
> BOOT-INF/lib/logback-core-1.5.38.jar
> BOOT-INF/lib/log4j-to-slf4j-2.25.5.jar
> BOOT-INF/lib/log4j-api-2.25.5.jar
> BOOT-INF/lib/jul-to-slf4j-2.0.18.jar
>
> 78
> ```
>
> 本案例工程的可执行 jar 里嵌了 78 个依赖 jar。这个数字本身也是个体检指标 —— 突然变大很多，通常是引入了某个重量级 starter。

运行可执行 jar：

```bash
java -jar target/activity-server-1.0.0.jar
```

> **关于官方教程的一个观察**
>
> 官方这篇入门教程到“创建可执行 jar”就结束了 —— **它没有测试章节**。这个安排可以理解（入门先跑起来最重要），但也导致很多人学完入门后完全不知道怎么写测试。本教程把测试单独放在[第 9 篇](09-测试.html)系统讲，案例工程从一开始就配套测试。
