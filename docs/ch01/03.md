# 三、案例项目 activity-server 起步

现在把 Hello World 扩展成案例项目的第一版。这一版只做三件事：建好分层结构、配好数据源、暴露一个健康检查接口 —— 让工程骨架先立起来，业务在第 4 篇展开。

### 3.1 完整 pom.xml

这是案例工程实际使用的 `pom.xml`，注释说明了每个依赖为什么存在：

`activity-server/pom.xml`

```xml
<?xml version="1.0" encoding="UTF-8"?>
<project xmlns="http://maven.apache.org/POM/4.0.0"
         xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance"

    <parent>
        <groupId>org.springframework.boot</groupId>

        <relativePath/>
    </parent>

    <groupId>com.example</groupId>
    <artifactId>activity-server</artifactId>
    <version>1.0.0</version>
    <name>activity-server</name>
    <description>校园活动服务平台 —— Spring Boot 4.1.1 案例教程配套代码</description>

        <dependency>
            <groupId>org.springframework.boot</groupId>

        </dependency>

        <!-- H2 内存数据库：教学场景零配置 -->
        <dependency>
            <groupId>com.h2database</groupId>

            <scope>runtime</scope>
        </dependency>

        <!-- 测试：4.x 按模块拆分的测试 starter -->
        <dependency>
            <groupId>org.springframework.boot</groupId>
            <artifactId>spring-boot-starter-webmvc-test</artifactId>
            <scope>test</scope>
        </dependency>
    </dependencies>

                <groupId>org.springframework.boot</groupId>
                <artifactId>spring-boot-maven-plugin</artifactId>

        </plugins>
    </build>

```

#### 为什么测试只引一个 starter

`spring-boot-starter-webmvc-test` 是 4.x 拆分出来的细粒度测试 starter，它已经传递引入了 `spring-boot-starter-test`（提供 JUnit Jupiter 6、AssertJ、Mockito）以及 `spring-boot-webmvc-test`（提供 `@WebMvcTest`、`@AutoConfigureMockMvc`）。也就是说，Web 应用只需要写这一个依赖。

### 3.2 主类

`src/main/java/com/example/activity/ActivityServerApplication.java`

```java
package com.example.activity;

import org.springframework.boot.SpringApplication;
import org.springframework.boot.autoconfigure.SpringBootApplication;
import org.springframework.boot.context.properties.ConfigurationPropertiesScan;

@SpringBootApplication
@ConfigurationPropertiesScan
public class ActivityServerApplication {

    public static void main(String[] args) {
        SpringApplication.run(ActivityServerApplication.class, args);
    }

}
```

> **为什么多了一个 @ConfigurationPropertiesScan**
>
> 案例工程有一个自定义配置类 `config/AppProperties.java`，用 `@ConfigurationProperties` 绑定 `activity-server.*` 前缀的配置项。这个注解**不会**被组件扫描识别，必须额外用 `@ConfigurationPropertiesScan`（或 `@EnableConfigurationProperties(AppProperties.class)`）才会注册成 Bean。少了它，配置类不报错，但注入处会提示找不到 Bean —— 第 3 篇会完整演示这个机制。

> **主类的三条约定**
>
> 一、放在根包 `com.example.activity` 下，而不是某个子包里 —— 这样组件扫描才会覆盖全部子包。
> 二、类上只加 `@SpringBootApplication`，不加别的注解。
> 三、启动日志里会打印这个类的全限定名，排查“配置没生效”时先确认启动的是不是你预期的那个类。

### 3.3 配置文件

这一版的 `application.yml` 只保留必要项，完整版在第 3 篇展开：

`src/main/resources/application.yml`

```yaml
spring:
  application:
    name: activity-server

  # H2 内存库：DB_CLOSE_DELAY=-1 保证最后一个连接关闭后数据库不被销毁
  datasource:
    url: jdbc:h2:mem:activity;DB_CLOSE_DELAY=-1;MODE=MySQL
    driver-class-name: org.h2.Driver
    username: sa
    password: ""

  jpa:
    hibernate:
      ddl-auto: create-drop
    # 让 data.sql 在 Hibernate 建表之后执行，否则初始化数据会因“表不存在”失败
    defer-datasource-initialization: true
    # 关闭“在视图渲染期间保持 Session 打开”，避免掩盖 N+1 问题
    open-in-view: false

  sql:
    init:
      mode: always

server:
  port: 8080
  shutdown: graceful

management:
  endpoints:
    web:
      exposure:
        include: health,info,metrics

logging:
  level:
    root: info
    com.example.activity: debug
```

> **两个配置项值得单独记住**
>
> **`defer-datasource-initialization: true`**：JPA 用 `ddl-auto` 建表、同时用 `data.sql` 灌数据时，默认情况下脚本会跑在建表之前，导致“表不存在”错误。加上这行让脚本等建表完成后再执行。
>
> **`open-in-view: false`**：默认值是 `true`，它让数据库连接一直保持到 JSON 渲染结束。看起来方便，实际会掩盖 N+1 查询问题 —— 因为懒加载属性在 Service 层之外也能被访问。开发期就关掉它，问题会立刻暴露出来（第 6 篇会用一个真实案例演示）。
