# 篇章地图与学习路径

## 四个阶段

| 阶段 | 篇章 | 内容 | 产出 |
| --- | --- | --- | --- |
| 一 · 起步 | 第 0 – 2 篇 | 4.x 相对 3.x 变了什么、环境准备、Maven 构建、代码分层、自动配置与依赖注入 | 一个能跑起来的 REST 接口 |
| 二 · 核心能力 | 第 3 – 8 篇 | 配置管理、Profiles、日志、Web 层、安全认证、数据访问、缓存与校验、消息通信 | 带认证、能读写数据库、有缓存的完整后端 |
| 三 · 工程化 | 第 9 – 11 篇 | 测试策略、可观测性与监控、打包与容器化部署 | 可测试、可监控、可部署的制品 |
| 四 · 全端交付 | 第 12 – 13 篇 | Vue 3 + Element Plus 管理端、接口联调、认证贯通、一体化部署 | 前后端分离、能交付使用的全端项目 |

## 各篇要点

### 起步

**第 0 篇 · [开篇：版本核实与学习地图](/ch00/)**

- 4.1.1 是不是最新稳定版——版本核实的三种可靠手段
- 3.x 到 4.x 的破坏性变更全景：starter 改名、模块拆分、Jackson 3、测试包迁移
- 环境准备：JDK、Maven、IDE，以及国内镜像加速
- 贯穿全教程的案例项目与技术选型

**第 1 篇 · [入门：环境、构建系统与第一个应用](/ch01/)**

- 官方入门教程的完整复现，逐行解释每个注解的作用
- Maven 构建系统：parent、starter、插件三件套；Gradle 对照写法
- starter 命名体系在 4.x 的变化与选择建议
- 可执行 jar 的原理与热部署（DevTools）

**第 2 篇 · [工程结构、自动配置与依赖注入](/ch02/)**

- 主类为什么必须放在根包：组件扫描、实体扫描、仓库扫描的实际范围
- 分层组织（web / service / repository / domain / dto）与按领域组织的取舍
- 自动配置的运作机制、条件注解、按需替换与排除
- Bean 与依赖注入：构造器注入、多个候选 Bean 的抉择、Bean 生命周期

### 核心能力

**第 3 篇 · [核心特性：外部化配置、Profiles 与日志](/ch03/)**

- 配置的十来种来源与优先级；`@Value` 在多环境项目里为什么会失控
- `@ConfigurationProperties` 的类型安全绑定、校验与 IDE 提示元数据
- Profiles 的四种激活方式，生产环境的配置分离策略
- 日志：级别调整、日志分组、JSON 结构化输出、文件滚动
- JSON 序列化（Jackson 3 的迁移要点）、国际化、AOP、任务调度

**第 4 篇 · [Web 层：MVC、REST 接口与异常处理](/ch04/)**

- REST 接口的分层设计：控制器只做协议转换，业务规则放 Service
- 统一响应体与全局异常处理；HTTP 状态码与业务错误码的分工
- 参数校验：内置注解、分组校验、自定义校验器、方法级校验
- 分页、排序、动态条件查询的接口设计
- 文件上传下载、静态资源、拦截器与过滤器、跨域、优雅停机

**第 5 篇 · [安全：Spring Security 与 JWT 认证](/ch05/)**

- 过滤器链的执行顺序与短路机制：搞懂这条链，Security 的报错就不再神秘
- 基于 JWT 的无状态认证：登录、签发、校验、刷新、注销
- 方法级授权、基于角色与权限的访问控制
- 密码存储、CSRF、CORS 的实际配置，以及常见错误排查

**第 6 篇 · [数据访问：SQL、JPA 与 MyBatis-Plus](/ch06/)**

- 数据源配置、连接池调参、HikariCP 的实战参数
- Spring Data JPA：实体映射、派生查询、`@Query`、分页与排序
- 事务：传播行为、失效场景（自调用、私有方法、异常类型）、只读事务
- N+1 问题的发现与三种解法；`open-in-view` 为什么必须关掉
- MyBatis-Plus 接入 Spring Boot 4：starter 选择、分页插件注册的坑
- SQL 初始化与版本化迁移（Flyway）；Redis 缓存与 NoSQL 要点

**第 7 篇 · [缓存、校验与外部服务调用](/ch07/)**

- 缓存抽象：`@Cacheable` / `@CacheEvict`、key 生成规则、自调用陷阱，含 SQL 条数实测
- 缓存穿透、击穿、雪崩的区别与应对；多实例下的不一致问题
- 参数校验：`@Valid` 与 `@Validated` 的分工、分组校验、自定义约束
- 配置项校验：让配错在启动时就暴露
- `RestClient` 调用第三方接口：Boot 4 的模块拆分、超时配置、三类失败的分类处理
- 定时任务：`fixedDelay` 与 `fixedRate`、调度线程池、集群下的重复执行
- 邮件发送的超时陷阱；Quartz 与 `@Scheduled` 的取舍

**第 8 篇 · [消息与实时通信：Kafka、AMQP 与 WebSocket](/ch08/)**

- 什么时候该上消息队列：解耦、削峰、异步的判断标准，以及不该上的情况
- Kafka：Boot 4 新增的 `spring-boot-starter-kafka`、key 与分区的选择、偏移量提交
- 消费失败的处理：重试与死信主题（默认后缀 `-dlt`，含实测）
- RabbitMQ：交换机模型、发布确认与退回、死信队列、JSON 消息转换器的新旧类取舍
- WebSocket 与 STOMP：三种前缀的分工、客户端包名在 7.0 的迁移
- 三条链路的测试手法：起真 broker、不连 broker、连真端口

### 工程化

**第 9 篇 · [测试：单元测试、切片测试与 Testcontainers](/ch09/)**

- 测试分四层，附各层实测耗时
- 4.x 的测试模块拆分，以及一批切片注解的包名迁移对照表
- `@MockitoBean` 取代已删除的 `@MockBean`；`MockMvcTester` 的 AssertJ 写法与实测坑
- 四种 `webEnvironment` 的取舍；真实端口下 `@Transactional` 不回滚服务端数据
- Testcontainers 2.0 的四项变化，以及拉不到 ryuk 镜像时的三种处理

**第 10 篇 · [生产就绪：Actuator 与可观测性](/ch10/)**

- 端点默认暴露面与 `exposure.include`；未暴露的端点为什么返回 404 而不是 403
- 4.x 的三处搬迁：`HealthIndicator`、`MeterRegistryCustomizer`、`EndpointRequest`
- 健康检查组件、存活与就绪探针、`info` 端点的开启条件
- 指标：注入注册表而非静态方法、低基数标签、Prometheus 命名转换
- 测试环境里真实指标导出被换成 `SimpleMeterRegistry` 这件事
- `loggers` 端点、自定义端点、端点安全的三道防线

**第 11 篇 · [打包与部署：可执行 jar、容器与原生镜像](/ch11/)**

- 可执行 jar 的目录骨架与 MANIFEST 关键字段；依赖占了 99.6% 的体积
- 4.x 的 `jarmode` 从 `layertools` 换成 `tools`，`extract --layers` 的行为变化
- 分层索引按变化频率切四层的原理与实测启动耗时
- AOT、CDS、两者叠加的效果与约束
- 镜像构建：`COPY --chown` 与 `COPY` 后 `chown` 的体积差异
- Buildpacks 与 Dockerfile 路线的取舍
- GraalVM 原生镜像：编译耗时、产物体积、启动时间与内存占用
- 上线前的配置：环境变量覆盖、容器内存感知、日志走标准输出

### 全端交付

**第 12 篇 · 全端实战（一）：Vue 3 + Element Plus 前端**（整理中）

- Vite 工程搭建与目录约定，与后端仓库如何组织
- 请求层封装：Axios 实例、拦截器、统一错误提示、Token 注入
- 路由与权限：动态菜单、登录守卫、按钮级权限
- 列表页范式：查询表格、分页、弹窗表单、批量操作

**第 13 篇 · 全端实战（二）：联调、认证贯通与交付**（整理中）

- 开发期跨域与代理的三种解法，以及各自适用的场景
- JWT 认证在全链路的贯通：登录、存储、刷新、失效处理
- 接口契约管理与文档（OpenAPI）自动生成
- 前后端一体化部署：Nginx 托管静态资源与反向代理
- 交付清单与验收自查表

## 阅读建议

第一次读，建议按顺序从第 0 篇读起，尤其是第 3 篇的配置管理和第 6 篇的数据访问，这两块决定了后面所有章节的代码风格。

若带着具体问题来查，直接跳到对应篇章即可。每篇开头标注了对应的官方章节，遇到拿不准的地方回官方原文核对；每篇末尾有"常见问题"表，按"症状、原因、解法"列出来，报错时先查表。
